# Activation and continuous progression

This phase implements the existing World activation contract first. The ordinary scheduling extension adds `order: "fixed"` and `order: "priority"` beside the specified default `"shuffle"`. Priority accepts a pure synchronous `priority(member)` callback; lower finite numbers run first, with source order resolving ties. Priorities are captured before actions. Fixed order consumes no randomness. All variants capture unique entry membership, exclude births, skip dead members, validate ownership at visit, and never advance tick.

`world.activate`, `world.report`, and `world.select` preserve scoped self/caller/death semantics. The pinned NetLogo scheduling variant requires its separately specified MT Random implementation; a Mulberry stream rejects rather than pretending to be compatible. Activation implementation belongs under `src/world/activation`, following the binding domain layout.

`twoPhase(source, { compute, commit })` captures unique original references, computes every proposal before the first commit, and commits in captured order. Compute and commit are synchronous. A failed compute performs no library commits; callbacks remain responsible for their own effects. A failed commit retains earlier commits. It has no clock, scheduler, membership owner, rollback, or implicit Random. Models should compute detached proposals and keep compute pure.

`continuous.linear({ value, rate, duration })` returns `value + rate * duration`. `continuous.crossing({ from, to, threshold, duration, direction? })` returns a detached `{ elapsed, value, direction }` or undefined. The model declares its quantity and time units; rate is quantity per time unit. Duration is finite nonnegative; all supplied numbers and calculated results must be finite. Crossing uses strict start/inclusive end: rising `from < threshold && to >= threshold`, falling `from > threshold && to <= threshold`. A start exactly at threshold does not fire; moving away and returning can fire again. Constant segments and zero duration do not cross. Direction defaults to either. Crossing time is linear interpolation with ordinary IEEE-754 arithmetic, exact only for the assumed linear segment; there is no general ODE solver or root tolerance.

Stopping, step budgets, and outcome reasons use the existing `studies.run` contract. No competing runner is added. World tick, Agenda time and elapsed physical duration remain distinct. Groups use caller objects as Graph nodes, graph edges for membership, and frozen native snapshots of neighbors; no parallel group registry is needed.

The five public scripts in `examples/model-dynamics` are the phase acceptance contract. They cover deterministic activation/lifecycle, seeded scheduling, two-phase updates, linear thresholds, and Graph membership combined with study stopping. Runtime implementation must preserve these assertions.

## Agenda membership

The binding World attachment contract extends its existing owner protocol to Agenda and Graph. `world.add` and `world.delete` accept one component or a finite iterable, identity-deduplicate at entry, and validate the complete batch before mutation. `world.agendas` and `world.graphs` are frozen insertion-order snapshots of canonical references. Agenda attaches to at most one World through the existing private framework record, with no competing ownership map. Detachment preserves events/time, registration never dispatches or advances any clock. The four `examples/graph-attachment` scripts freeze identity, mixed batch, conflict atomicity and snapshot guarantees before Agenda attachment runtime changes.

Priority evaluation skips members already dead at entry, before calling the priority projection. It does not prevalidate living ownership: a foreign living member still fails at its scheduled visit after any earlier action effects. Nested death signals unwind through inner frames until their own owning frame consumes them. Two-phase processing is generic data composition: it performs no implicit lifecycle filtering or ownership checks. A model needing such checks supplies explicit model rules. Threshold endpoints preserve the supplied duration exactly when `threshold === to`; rounded elapsed time remains in `[0, duration]`. Subnormal crossing times may underflow to zero; no epsilon or repeated-event suppression is inferred.
