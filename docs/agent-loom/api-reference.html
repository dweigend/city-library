Model properties

Agent, Field and Edge expose the supplied state as ordinary typed properties. Choose names, scalar values and nested data for the model; only the documented library members are reserved. There is no required properties, metadata or UI wrapper. Declare properties in the initial state or its ordinary TypeScript type; later assignments follow that type.

The library supplies logic, identity, spatial state and data access. It supplies no built-in appearance properties, drawing commands or presentation defaults. Names such as color, size, shape, label, hidden and selected are available as custom model data with no special library meaning. A custom radius or size affects a physical calculation only when the model explicitly uses it. External applications decide how to display any property and may use Input for constrained edits.

import { Agent } from "agent-loom";

  attributes: { occupation: "carpenter", experience: 12 },

person.energy -= 10;
console.log(person.role, person.energy); // worker, 70

The same supported-value and reserved-name rules apply to field and edge state. Construction and copy create independent supported data graphs; later direct assignment uses ordinary TypeScript reference semantics. Storage preserves declared custom data without a separate presentation schema. Readonly membership/query arrays retain the original objects, so consumers can read their current typed properties. Model-wide records and indexes use ordinary objects, arrays, Map or Set and can be included explicitly in storage.

Direct state and identity

Behavior and errors

Agent state, field state and edge state are own string-keyed data properties of a plain record. A supplied direct record is copied once per new individual/field/edge. The copy traverses plain records, arrays, Map, Set, Date, RegExp, ArrayBuffer and standard non-shared TypedArray/DataView views. It preserves cycles and repeated references within one clone, including shared backing buffers across views, and creates fresh containers between independent copies. RegExp requires lastIndex to be a nonnegative safe integer and preserves source, flags and lastIndex; ArrayBuffer/views preserve bytes, offsets and shared backing identity. SharedArrayBuffer, detached buffers and active resources reject. Ordinary numbers must be finite: NaN and positive/negative Infinity reject, while negative zero is preserved. Typed-array bytes may contain any IEEE pattern as opaque byte data; numeric operations still validate finite scalar values they consume. Undefined, null, boolean, string and bigint are allowed. Sparse array holes are preserved; extra named array properties reject. Dates must have finite valid times. Symbol keys, accessors, functions, weak collections, DOM objects, Error objects and custom prototypes reject. Proxies and objects with observable access behavior are unsupported caller inputs; JavaScript provides no universal Proxy detector, and access failures propagate before publishing a component. Framework component references preserve identity rather than being recursively copied; a deleted component reference rejects. These references never attach components implicitly. The same supported-value rules apply to Agenda event data, extra state supplied to storage.save and ordinary fixed-step experiment payloads. History and statistics impose their documented finite numeric schemas.

The following reserved-name lists are complete for target major version 1; reject these keys on the corresponding root state record. Agent reserves id, alive, world, x, y, z, heading, pitch, roll, copy, delete, move, rotate, distanceTo, directionTo, neighbors, canMove and gradient. Field reserves id, grid, x, y and z. Edge reserves id, graph, alive, from, to, directed, key, path, delete, tie and tieMode. Adding a reservation for an otherwise valid model key requires a new target major version. These lists concern root model state, not nested records or closed API options. Object.prototype spellings such as constructor and __proto__ remain valid data when not listed, using safe own-data property creation rather than prototype assignment. The library reserves no additional spelling merely because it appears in examples. Construction snapshots the initial data; later direct assignments follow ordinary TypeScript reference semantics. Two agents can deliberately share an object by assigning it after creation. Neither direct state assignment nor native array mutation performs library membership bookkeeping. A snapshot follows the actual reference graph when saved and rejects unsupported values introduced since construction.

agent.copy() requires a living source and creates a detached living identity with copied custom state, position and orientation using the rules above. It consumes no draw and does not copy graph membership, World membership, path progress or Input bindings. New Agent/Field/Edge and component identity IDs are unique among all issued such identities within the process; local EventHandle IDs and Graph edge keys have their separately documented owner scopes. A private process-local monotonic bigint allocator assigns fresh opaque strings, including on load; it is technical identity allocation, not a model RNG or creation-order API. Allocation never reuses a previously issued process-local string, and needs no serialized model counter. IDs from separate processes have no cross-process uniqueness promise. Persist meaningful numeric/domain IDs as ordinary model data; opaque framework IDs are not stable persistence keys. Copy has no options; modify the returned individual's direct state explicitly. A deleted agent retains readable final state and identity; all library mutators and spatial queries on it reject, except repeated agent.delete(), which is a no-op. Living detached agents remain usable. Deletion removes incident edges and node membership in every graph retaining that agent, removes World membership and Input bindings, discards path progress, and never removes references from caller-owned arrays.

Pure domain operations

These synchronous value functions validate all inputs and return detached data. They never attach components, mutate caller data, advance clocks or use hidden randomness. Shape failures throw TypeError; out-of-domain quantities and nonfinite intermediate results throw RangeError. No option is implicit except the defaults explicitly stated below. Monetary and capacity arithmetic uses safe integers; spatial and time units are selected consistently by the model.

Behavior and errors

The World creates and retains one Tick. Its reference and value are read-only; there is no separate Tick constructor. Advance and reset change only this clock. They do not execute rules, change agents or fields, dispatch Agenda events, record History samples or consume random values. Reset does not restart the model.

Advance rejects a nonnumeric amount with TypeError and a negative or nonfinite amount, or a nonfinite resulting value, with RangeError before changing the value. Fractional amounts use ordinary JavaScript number arithmetic. Both methods reject while their owning World is running, including calls from nested callbacks. Other Worlds remain independent.

History sample fields and model measurement keys use the numeric name tick; supply world.tick.value as that value. Snapshot WorldRecord.tick likewise stores this number; load creates the World-owned Tick with the saved value. Reset leaves History and Agenda untouched. Call history.delete() or replace the History before recording a lower tick value.

Run model steps

  ([Extract<R, PromiseLike<unknown>>] extends [never] ? unknown : never), steps?: number): void

Import run from agent-loom. It invokes the supplied synchronous step function, then advances the supplied World’s time. It is the single public entry for advancing model steps; no parallel world.run or script alias is proposed. It does not activate agents automatically.

InputDefault / required valueMeaning
steps1Nonnegative integer count; 0 runs no rules.
worldRequired WorldExplicit context whose tick value advances; no global current World.
stepRequired synchronous functionThe model chooses which collections/actions run and in what order. Named functions are the documentation style; inline callbacks are also valid TypeScript.

Result and effects: Validate World, callable step and a finite nonnegative integer steps before execution. Each successful step increases world.tick.value by 1. Then consumers may observe. Behavior and errors

Component means Agent, Grid, Graph, Input or Agenda. Readonly collections are insertion-order snapshots of original references, not writable membership views. Batch attachment first consumes the finite iterable into a duplicate-free snapshot, validates all objects and dependencies, then attaches all or none. Iteration errors occur before changes. A single add returns that component; a batch returns the normalized snapshot. A component has at most one World owner. Reattachment to the same World is a no-op and does not reorder it. Graph nodes do not become World agents by graph attachment.

World deletion only detaches; it does not delete the component. Batch detachment has the same validation rule. A missing unowned component or component already absent from this World is a no-op; a component belonging to another World rejects. Input bindings are explicit dependencies: an attached Input cannot point to a framework component owned by a different World. Detaching one side is allowed because absence of ownership is compatible; moving that side into another World rejects until the dependency is removed. Ordinary graph nodes may be shared by identity; framework component nodes attached elsewhere reject when graph or node ownership is changed. Validate these constraints across the resulting complete batch, allowing related components to transfer together only after explicit detach. No graph operation silently transfers ownership.

run defaults to one step and accepts finite safe-integer steps ≥ 0. Before the first callback validate the World, callback, finite world.tick.value + steps and representable +1 progress for every planned clock increment. Formally preflight the same IEEE-754 recurrence t0 = world.tick.value; t(i+1) = t(i) + 1, requiring every planned result finite and strictly greater than its predecessor. Zero steps requires no increment. This is a numeric-progress condition, not a safe-integer restriction on tick. Declared async functions reject before invocation; callable callbacks returning a Promise/thenable reject after invocation and before tick advancement. Type checking excludes a statically known Promise return; untyped host input still requires the runtime checks. Nonthenable return values are ignored. Each successful callback increases world.tick.value by 1, counting one completed model update in the default clock convention. Explicit fractional clock advances outside run do not represent additional completed callbacks. Exceptions stop immediately, retain earlier model effects and successful ticks, and do not increment the failed step. Reentrant run on the same World rejects; separate Worlds can run synchronously. No implicit event dispatch, activation, measuring, saving, rendering or wall-clock waiting occurs. Async work already started by a misdeclared callback cannot be cancelled or rolled back.

Identity and protected bookkeeping

Behavior and errors

World options are observable as immutable world.space and world.random plus explicit model state. world.agents, attached grid.fields and graph.nodes/edges expose original identities through readonly views/snapshots. Resolve IDs using native find over those views, returning undefined for absent/deleted identities; array position is never an ID. Immutable IDs and saved continuation metadata replace writable registry/counter access. World membership changes use add/delete, lifecycle mutations use delete and the clock uses world.tick.advance/reset. Loading issues fresh opaque framework IDs and preserves explicitly captured model-owned numeric IDs/counters. The private process allocator never reuses a live or previously issued process-local ID; no global model counter is inferred from public IDs. Persistent indexes must use captured component references or model-owned keys, and an index keyed by opaque IDs must be rebuilt after load. Active frame sets, raw identity registries, patch maps and counters remain protected implementation state: activation contexts expose scoped self/caller/lifetime, and observation exposes stable public identities without granting invariant-breaking writes. No modeling ability is removed by protecting those internals; native Map indexes may cache public IDs provided the model updates its own cache at lifecycle boundaries.

Behavior and errors

Default scripts use ordinary arrays, loops, filtering, Set and Map. Array iteration consumes no RNG and does not acquire NetLogo ask semantics. Explicit World activation supplies the optional synchronous scheduling/context capability; it does not change the model language or replace independently created components. The pinned compatibility profile is netlogo-7.0.0 from the existing verified baseline; current NetLogo documentation is a separate capability reference, not evidence that this profile reproduces later releases bit-for-bit.

Sources are ordinary data and original object references. An array captures unique membership in first-occurrence order; global-kind selectors resolve current live World membership at invocation. A graph attachment does not attach its nodes; only registered World agents qualify as agents, while fields and edges must belong to attached owned components. Live-selector creation itself performs no traversal or random draw; reuse the same plain selector to see later births/deaths. Filtering with native TS captures an ordinary array; no library Population wrapper exists.

order defaults shuffle: capture and identity-deduplicate at entry, run a complete descending Fisher–Yates copy through world.random before any callback, and skip members dead before their visit. Living ownership is validated at visit after shuffling, preserving partial failure: earlier callbacks and draws remain when a later foreign member fails. A one-element array still has no shuffle draw, whereas a native single source has no traversal at all. Births during callbacks never join an invocation. select never shuffles: visit entry membership in deterministic source order, evaluate Boolean predicates on still-live members, retain original references still alive after true. Nonboolean (including death-unwound undefined) rejects without undoing earlier effects. A predicate may deliberately mutate/draw, so select with a callback is not automatically a pure query.

order netlogo-7.0.0 requires the MT compatibility RNG, explicit XY members, and compatible contexts. Global agents are sorted by ascending numeric compatibility IDs, fields by descending Y then ascending X, and edges by canonical numeric endpoint IDs then breed declaration order; captured arrays retain captured order. Implement forward lazy selection: at position i draw Java nextInt(n-i) when at least two remain, swap the chosen remaining item into i, then prefetch the following item before invoking the current callback. Captured/field sources filter dead values while prefetching; tree-like global-agent/edge/breed sources defer that dead check until traversal. This prefetch timing is observable when callbacks draw or kill later members. A singleton direct member draws no traversal RNG. Only observer calls may activate the special global agents/fields selectors; report permits those selectors from nested contexts. NetLogo-compatible breed selectors retain declaration provenance, never silently becoming a captured array. Core IDs are opaque strings and cannot supply native numeric ordering: for global agents/edges supply ids as a same-World identity-to-unique-nonnegative-safe-integer Map; breed selectors use breeds and breedOrder (distinct declared names) to recover model-owned role membership/order. Global field ordering needs coordinates only. Validate the complete mappings and ownership before drawing; absent required numeric IDs, unknown breed names, duplicate IDs or a foreign map key reject. Captured arrays already retain their own order and may omit those maps. Imported legacy conversion metadata can provide these maps explicitly; no random or ID-allocation inference occurs.

Each callback receives original self/world, caller as the immediate explicitly supplied outer context's self (absent for observer calls), and scoped die. Nested JavaScript alone does not imply caller: pass the active context explicitly. Expired/foreign contexts reject before traversal. Reading caller preserves the immediate identity even during death unwinding; model-held references to deleted identities retain ordinary object semantics. die deletes self and immediately throws a private frame signal; fields cannot die, inactive frames reject. JavaScript catch/finally remains observable. Ordinary agent.delete() deletes but does not return from user code. No operation adds ticks. Frames expire in finally after return, death or error. Async/generator callbacks reject before traversal; returned thenables reject after invocation without rollback. Callback errors propagate after frame cleanup; only the frame's own private death signal is consumed.

Behavior and errors

Full extent L is centered on zero. Hard movement accepts coordinates in the closed interval [−L/2,L/2]; wrapped coordinates normalize to [−L/2,L/2). A hard relative displacement follows the straight displacement vector until the first boundary intersection, rather than clipping each coordinate independently. Absolute placement outside any hard axis rejects atomically. The active World context is authoritative; an explicit context must be value-equivalent or rejects. Without World space, explicit context applies; otherwise coordinates are unbounded. Dimension mismatches reject before mutation, including a z component of zero supplied to an XY operation. Pure distance uses Euclidean length of shortest per-axis displacement. At an exact wrapped half-extent tie, choose the negative displacement; this fixed tie rule applies to perception, facing and wrapped path travel.

directionTo validates a living source, finite compatible target and the distance operation's context precedence/equality rules. It returns undefined for coincident positions. Otherwise heading is atan2(dx,dy) in degrees normalized to [0,360); XYZ pitch is atan2(dz,hypot(dx,dy)) in [−90,90]. Use shortest wrapped displacements and the negative half-extent tie rule. For vertical XYZ displacement, heading is the source's current canonical heading and pitch is ±90. XY result omits pitch. Return frozen detached direction data without changing orientation, state, time or RNG. This bearing reporter does not report roll or perform movement; rotate({towards}) owns facing.

The default 3D basis is right +X, forward +Y, up +Z. Orientation is stored as an orthonormal right-handed basis (or equivalent unit quaternion); coordinates alone never encode roll. The public heading/pitch/roll values describe composition H·P·R: H is a clockwise world-Z rotation, P is a positive local-right rotation raising forward toward +Z, and R is a positive local-forward rotation taking right toward −up. Relative rotate(angle,{axis}) uses the current local axis: x applies P, y applies R, z turns forward toward right. In XY only z is valid. Default angle zero preserves all basis values; finite angles are reduced modulo 360 before composition.

For extraction let f be forward and r be right. Pitch = asin(clamp(f.z,−1,1)) in degrees, in [−90,90]; outside a pole heading = atan2(f.x,f.y), normalized to [0,360). Let r0=(cos H,−sin H,0) and u0=r0×f. Roll = atan2(−r·u0,r·r0), normalized to [−180,180). At |cos pitch| ≤ 1e−12 use heading = atan2(−r.y,r.x), roll = 0, preserving the represented basis when reconstructing. Public readback is a canonical representation; the underlying basis is not reconstructed after each read. Every composition renormalizes the basis; no native NetLogo transcendental bit equality is promised. Facing a target sets shortest-displacement forward and roll zero; coincident targets preserve orientation. For a vertical target preserve prior heading and use pitch ±90. Facing uses the same optional space context option as distance and move.

Path distance defaults to one spatial unit, must be finite and nonnegative, and is unrelated to an edge's economic/time cost. A path is a nonempty readonly coordinate sequence. On first use its first point is the first waypoint; it need not equal the current position. Validate and snapshot every waypoint before moving; remember both path-object identity and its coordinate fingerprint. Later reuse rejects changed coordinates, changed length or changed active context. Direct movement cancels progress. Switching path identity starts from the current position toward the new first waypoint. Consume distance over successive shortest wrapped segments, skipping zero-length segments without spending budget. Update forward along the last nonzero traveled segment, retaining roll zero. Reaching the final point returns true; later calls with that unchanged path return true without movement. A zero budget returns whether already at the final point after zero-length waypoint processing. All hard waypoints must validate in bounds before movement; straight segments between them therefore remain in bounds. No route segment is silently clipped into a different route. Movement never chooses a route, computes acceleration or advances a clock. Snapshot continuation includes waypoint snapshot, cursor, context and path association within a captured root graph; callers reusing a restored path must use that restored path identity.

Behavior and errors

This optional motion relation uses an existing edge whose endpoints are live Agents. New edges have tieMode "none"; tie() defaults to "fixed", "none" removes the relation, and repeating the current mode is a no-op. The stored from endpoint is the parent and to is the child, including when the connection is undirected for graph traversal. This explicit parent relation is independent of routing direction. No new component or authoring language is introduced. Plain data/field nodes, loops and deleted endpoints cannot be tied.

The active parent relation over all graphs containing those Agents must be a forest: each child has at most one active parent and no cycle is allowed, including parallel constraints or a cycle spanning multiple graphs. Activating a relation validates the entire resulting component before mutation. All members must have the same XY or XYZ dimension and either belong to the same World or all be detached. Their selected spatial contexts must be value-equivalent. A standalone explicit movement context applies to the whole detached component for that call. Invalid relations throw without changing the previous mode or any Agent. Switching fixed/free preserves current positions and orientations and establishes no hidden rest-length value.

Every successful move or rotate on a parent propagates one transform down its currently tied descendants, in parent-first edge insertion order. For each parent, capture its position and orthonormal right/forward/up basis before and after the operation. Let D be the rigid rotation mapping the old basis to the new one. The child's new position is newParentPosition + D × (oldChildPosition − oldParentPosition). A fixed relation also applies D to the child's orientation basis; a free relation keeps the child's orientation unchanged while its position follows the parent's rotation and translation. Then compute that child's own before/after transform and recurse: descendants of a free child inherit its translation but no parent-induced orientation change. In XY, D is the ordinary clockwise heading rotation; in XYZ use the full orthonormal basis, including pitch and roll. This defines translation, orbital motion and orientation independently of Euler representation.

Movement on a child never propagates upward or to siblings; it changes that child's current relative placement, which subsequent parent transforms use. Both relation modes propagate parent translation. Absolute placement, displacement, scalar movement, path movement and explicit orientation changes all use the same propagation. A successful propagated position change clears that descendant’s own path association/cursor, so a later call with its old path restarts from the new position. A propagated orientation-only change retains its path cursor. Publish these cursor changes atomically with all positions and orientations; failed propagation preserves them all. A path call propagates its completed position/orientation transform once; it does not simulate vehicle joints, collisions, suspension or turn radii. Routing/graph algorithms ignore tieMode unless the model explicitly reads it.

Use minimum-image child displacement on wrapped axes before the rigid transform; an exactly half-extent separation chooses the negative displacement. Normalize each resulting wrapped coordinate afterward. Hard-axis constraints are validated for the root's normal movement result and every descendant before any changes commit. If any descendant would leave a hard context, throw RangeError and preserve all positions, orientations and route cursors. The root's ordinary displacement clipping still applies when every resulting descendant position is legal. Absolute placement of the root translates the whole affected subtree immediately, without traversing a path.

World attachment/detachment of an active tied component must move its complete tied tree together in the same explicit batch, or reject atomically; independent graph attachment still never attaches its nodes. Deleting an edge/node membership or Agent automatically removes its affected tie relation, preserving surviving Agents and their other ties. Graph.delete removes ties with its edges. Graph.copy creates untied edges even when its source edges are tied, so shared Agent identities do not acquire duplicate parents. Capturing/restoring continuation preserves tieMode only when all involved component roots are explicitly included; decode validates forest, identity, dimensions and ownership before load. No tie operation draws randomness or advances time.

Classification, references and validation

A direct World has rootKind world. A plain named record with one or more explicitly declared framework components, or arrays of them, has rootKind bundle. A direct individual component, an unwrapped array of components, or a component hidden only inside nested data is rejected; place the selected components in a named bundle. No automatic World or missing dependency is created.

Data roots and their extra state follow the shared supported-value and cloning rules, including cycles and aliases between ordinary values. They contain no live framework references. Format contract

id is a nonempty string of at most 128 UTF-16 units and version is a positive safe integer. They identify the selected adapter: library-generated format-validation errors include this id/version; callback exceptions are rethrown unchanged. Additional own properties on the format object may hold ordinary private configuration; the library neither interprets nor serializes those extra properties. Unknown properties on the encode/decode options object still reject. Encode and decode are synchronous nonthenable callbacks. They must preserve the complete supplied data contract, validate their own supported types, fields and numerical domains, and either return the promised result or throw. The decoded value type is established by the supplied validating function, not by selecting an unchecked generic type. Same-shaped forged objects are never accepted as framework snapshots.

Custom formats accept and return ordinary supported data only. A live component or Snapshot input/result rejects with TypeError; custom formats never create framework instances from records. To transform a model snapshot, first encode it with the built-in snapshot-json format, pass that ordinary string to the custom format, and reverse those explicit calls before the standard snapshot decoder and load. This keeps framework schema checks outside the custom callback and avoids nested snapshot-codec dispatch. Each explicit decode receives its own caller-supplied limits; options never propagate into unrelated calls implicitly. Ordinary decoded data is checked against shared supported-value budgets before publication.

The descriptor's id/version do not automatically add a header to the encoded bytes. The format owns its version information and compatibility checks, either in its document or in an explicitly agreed external schema. Neither callback performs hidden model mutations, random draws or file/network operations. Callback errors propagate; the library cannot roll back arbitrary callback side effects.

Custom text defaults to the existing 32 MiB UTF-8 limit; binary input/output uses the same byte ceiling. Caller DecodeLimits may lower the existing byte/depth/record/reference/item limits. Check that input is string or Uint8Array and enforce encoded bytes before calling decode; the formatter validates its particular expected input type; validate output type, bytes and supported-value counts before returning. The formatter must enforce any tighter format-specific limits while parsing/encoding. A generic limit is not a sandbox for trusted caller code.

Behavior and errors

The root export limits is one deeply frozen data object; the assignment notation above describes its readable fields, not writable configuration. Reading budgets invokes no allocation, callbacks, model clock or RNG. Counts are hard ceilings for their explicitly named bounded adapters, not targets to fill. netlogo applies to the pinned compatibility declaration/creation/value/distribution operations. geojson applies to planar dataset parsing/writing and containment. compatibilityNetwork retains the bounded simple-network import/validation profile: request it explicitly with storage.decode(text,{format:"legacy-network-json"}) or storage.decode(data,{format:"legacy-network-data"}); it does not impose a 1024-node cap on all live Graph models. behaviorspace applies to the finite-data XML parser including subexperiment records; study bounds materialized plans and completed-step/sample budgets. Lower caller caps may be supplied only where an operation documents them; higher caps reject. No resource value silently changes algorithm semantics or validates model science.

The legacy-simple network profile accepts unique nonempty string node IDs of at most 256 UTF-16 units, simple homogeneous directed or undirected unweighted edges, no loops/parallel pairs, at most 1024 nodes and 32768 edges. Validate endpoints, direction and complete shape, then return a detached canonical copy sorted by code-unit node ID and endpoint order. Both prior typed validation and unknown-data canonicalization map to this single boundary; malformed types throw TypeError and domain/count violations RangeError. General graph-json follows the richer Graph interchange contract and is a separate format.
