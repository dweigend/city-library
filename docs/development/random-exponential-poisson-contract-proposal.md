## Binding facts and five proposed scenarios

Use only existing `random.number({ distribution: "exponential" | "poisson", mean? })`; mean defaults to 1. Standard exponential is `-mean * Math.log(1-U)`, mean nonnegative, mean zero returns zero without a draw. Standard Poisson accepts mean in [0,100000], uses a product loop below 30 and transformed rejection at/above 30; zero returns zero without a draw. Invalid parameters and inapplicable distribution keys reject before drawing; sampled outputs must be finite and output overflow rejects after consumption without rollback. Distribution draws do not advance tick. Standard profile revision remains `agent-loom-random/1`.

## Current runtime and genuinely open closures

Read [random.ts](../../src/random/random.ts), [continuation.ts](../../src/random/continuation.ts), [normal.ts](../../src/random/normal.ts), [uniform.ts](../../src/random/uniform.ts) and [state validation](../../src/agent/state.ts). Current `Random.number` has uniform/normal overloads only; dispatch sends every non-normal option record into uniform validation, which rejects exponential/Poisson. The new distributions are absent, not merely inaccessible. Actual calls with mean1 both throw `TypeError: Unknown option: mean` without changing continuation; omitting mean instead reaches `TypeError: This slice supports uniform draws only.` Current defaults use recognized undefined as omission; closed plain option records reject symbol/accessor/unknown keys before draws. Existing normal cache is the unscaled companion stored in the same continuation; cache reads and normal deviation0 behavior are already delivered.

- **U1 — exact high-mean transformed rejection.** “Transformed rejection” does not identify PTRS versus PTRD, constants, floating evaluation order, factorial/log-factorial evaluation, squeeze/rejection order or number/order of uniform draws. Therefore the binding's revision label alone cannot yield high-mean golden values. Parent must choose and record the precise algorithm, endpoint behavior and continuation protocol before runtime/freeze. Scripts03/05 leave exact sampled values open while asserting scientific results and self-continuation.
- **U2 — product-loop stopping and tiny means.** Binding does not pin `<` versus `<=` at a threshold equality or whether the positive-mean loop is do-first. For positive subnormal mean, `exp(-mean)` rounds to1; a prechecked loop initialized with product1 can skip every draw and even produce −1 with a conventional count-minus-one return. Uniform U=0 must also have an explicit stopping policy. Mean0 no-draw is already binding. Proposal: choose a do-first positive-mean loop, explicit comparison and nonnegative count, but do not freeze this from the ordinary low-mean fixtures. Underflow of the product/threshold and any rejection/iteration limit need explicit decisions; no normal-sampler cap is inherited silently.
- **U3 — normal cache independence.** Proposal: both new families use only the uniform stream, leave any Gaussian companion unchanged, and require no new continuation fields. This is consistent with product/PTRS candidates and existing cache ownership, but the underspecified high-mean algorithm alone does not prohibit a Gaussian-based alternative. Script04 makes the uniform-only/cache-preserving proposal explicit for review. Copy/local/state semantics themselves are already binding and must not change.
- **U4 — numerical input and error details.** Poisson's range excludes infinities; exponential's nonnegative constraint does not explicitly repeat a finite-input qualifier. Proposal: require finite numeric means for both and reject invalid means before drawing, use existing optional-undefined defaults and closed descriptor-safe option records. Exact TypeError/RangeError classification/messages are not specified here; examples assert failure plus unchanged continuation, not new error text/classes. Signed input zero and sampled negative-zero sign are not frozen. Exponential output underflow is finite and needs no clamp. Reject a nonfinite sampled output after the consumed draw, preserving the already-binding no-rollback behavior.
- **U5 — algorithm identity and bounded rejection.** Before release, record the chosen high-mean recipe and low-mean comparison as the first concrete implementation of these revision1 branches; do not silently change existing uniform/normal traces. Neither Poisson input cap100000 nor result finiteness implies a result cap of100000. No arbitrary output clamp, Gaussian approximation, new public retry option, private fallback stream or new count limit is authorized. If an operational rejection limit is desired, choose its failure/consumption behavior explicitly first.

## Primary-source PTRS candidate, not a selected implementation

Hörmann, W. (1993), *The transformed rejection method for generating Poisson random variables*, **Insurance: Mathematics and Economics**12(1),39–45, [publisher/DOI](https://doi.org/10.1016/0167-6687(93)90997-4). The accessible author's [WU April1992 preprint](https://statmath.wu.ac.at/papers/92-04-13.wh.abs.html) was checked visually in its official PostScript rendering: printed p4 defines `G(u)=(2a/(0.5-|u|)+b)u+c`; Table1 p5 gives parameters; p7 prints **Algorithm PTRS**, using two uniforms per proposal, squeeze checks and log-Poisson acceptance. Crucially Table1 uses `c=mu+0.445`, while printed PTRS p7 uses `+mu+0.43` (PTRD uses+.445). This version discrepancy must be resolved explicitly before constants/traces freeze; no popular implementation was substituted. The primary formula location is supplied for choosing a candidate, not as copied code or a complete implementation specification.

The [WU repository PDF cover](https://research.wu.ac.at/ws/portalfiles/portal/18953249/document.pdf) labels its document license **Unspecified**. Publisher full-text reuse permission was not established. Shell PDF retrieval returned HTTP403; the official [PS.gz](https://statmath.wu.ac.at/papers/92-04-13.wh.ps.gz) was accessible and rendered locally with Ghostscript for inspection. Its gzip SHA-256 is `5dc06222f83c17384bc2f8022b30e14c7d4cdc380ce7e1a12dd816d9f43e8dcb` (47843 bytes); decompressed PostScript SHA-256 is `7ae552c669bce030976944142935a6e9bf71ac5df79659bf232e08a1b9aa1549` (119021 bytes). Neither the complete paper nor rendered pages are retained. No implementation text was copied. An independently written implementation still needs attribution/provenance and an explicit algorithm decision; this citation is no blanket license clearance for upstream code.
