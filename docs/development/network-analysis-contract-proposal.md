## Existing binding and public boundary

The [API table](../agent-loom/api-table.md#graph-analyze) and [complete centrality contract](../agent-loom/api-reference.md#graph-centrality-extended) already specify:

```ts

  disconnected?: "reachable" | "discount";
  cost?: (edge: Edge<N, E>) => number;
  weight?: (edge: Edge<N, E>) => number;
  damping?: number; tolerance?: number; maxIterations?: number

```

No renamed helper, new core public type, limited-measure stub or source-extension façade is proposed. The scripts use the existing public root `Graph`/`Edge` vocabulary; one purity witness uses already delivered Random/World. Current public Graph delivers neighbors/connectivity and the three recently delivered [distance methods](graph-distances-contract.md), but no analyze. Future accepted algorithms belong in focused graph algorithms, separate from the topology owner, with framework-independent maps and canonical node/edge references. UI consumes scores and model actions; it does not own a second centrality algorithm or topology.

A later implementation should use incidence accumulation for degree, positive-cost shortest-path traversals for closeness, Brandes-style dependency accumulation for betweenness, and the specified shifted-power/PageRank iterations. Repeated public distance calls must not accidentally recapture callbacks per source. Reuse the accepted shortest-path semantics and one captured query structure through an internal graph algorithm boundary; no new public preparer API is proposed. Exhaustive tiny-path enumeration below is only an independent oracle, not an implementation strategy.

Every result is a detached insertion-ordered ReadonlyMap containing **every canonical graph node**, including zero-score isolates; keys remain original identities. No query changes topology, model time or random stream. Readonly is an authoring contract, not a promise that freezing a Map magically disables `.set`; results must never expose an internal mutable cache.

### Independent rare-branch proof and exact small oracles

03 constructs a directed positive-cost DAG. One source→rare→merge path has exact cost1079+1. Its equally costly alternative has1080 successive stages, **two parallel unit-cost edges per stage**. Thus sigma(merge)=2^1080+1. Only source can reach rare; without tails rare has betweenness1/(2^1080+1), which genuinely rounds to zero. Add127 unique successors after merge: there are128 relevant destinations (merge plus tails), so rare's total is128/(2^1080+1). Other sources cannot contribute through rare.

Let m=2^-1074, the least positive binary64 value. Exact rational inequalities prove `1.5*m < 128/(2^1080+1) < 2*m`, so the unique nearest binary64 value is **2*m**, and the script asserts `2 * Number.MIN_VALUE` directly. The intermediate quotient1/(2^1080+1) alone rounds to zero; multiplying that rounded Number by128 is therefore wrong. The result is not a guessed exact Number or an absolute1e−10 comparison that would accept zero.

The one-off [oracle tool](network-analysis-proposal-evidence/verify-oracles.py) uses independent all-pairs vertex-simple path enumeration with Fraction costs for16 small stage/tail variants (stages2–5, tails0–3), proving the general rare formula in every enumerated case. The1080-stage graph is justified combinatorially, not enumerated. It additionally checks exact stationary equations for the new PageRank loop/MAX-row witnesses, the1e−16 closeness published-total calculation, large-prefix positive-cycle ordering, degree tie-to-even and finite-rounded MAX boundaries. [Results](network-analysis-proposal-evidence/oracle-results.json) include strict rational underflow inequalities, hexadecimal rounded value and unchanged scope: no analyze implementation executed.
