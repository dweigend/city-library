## Canonical ownership and the actual reusable dependencies

Use one World, one attached 171 × 115 Grid with hard axes, and one explicit Random. Patch centers are x = −85…85 and y = −57…57; geometric extents are 171 and 115, so physical endpoints are ±85.5 and ±57.5. No geographic CRS, meters-per-cell or currency conversion is specified. Radius and distance constants use source patch units. The World owns the sole scientific tick. A history segment label distinguishes reset epochs; it is not another advancing clock.

Each Field owns `landValue`, `water`, `electricity`, `transport`, `occupied`, `ctr`, `elevation`, `colonia` and retained numeric patch color. Each Agent owns its kind, spatial state and applicable breed properties. World membership supplies the only live population. Grid occupancy queries supply actual occupancy; the source's `occupied` field is a separate, deliberately stale model cache and must not be replaced with an occupancy query. Agent `works` references canonical employment-center Agents. Builder `origin` can be an inherited list of service-center Agents or, for a regularization builder, a Field. Read projections use opaque IDs for these references, never cloned live objects.

Model globals own `values`, `weights`, `marginalValue`, `marginalWeight`, `crossed`, `maxCost`, `thirdPhase` and `setupDone`. Initial source values are numeric zero, including `third-phase` and `setup-done?`; only later does the source assign strings/true. A boolean public `setupDone` can normalize the initial zero to false, but must not accidentally treat any nonzero/nonboolean fixture as completion. Keep `thirdPhase: 0 | "go" | "stop"` or explicitly document a lossless public naming conversion.

The source computes builder headings from numeric `who + 1`. Therefore a single model-owned birth ordinal, reset by CLEAR and allocated for **all** turtle births, is scientifically meaningful. Store the ordinal on the canonical Agent; do not parse opaque framework IDs or introduce another population registry. Native creation batch ordering, default random heading/color draws and hatch inheritance need explicit scheduling evidence. A port that ignores those implicit draws already has a different random schedule even if it calls the same named distributions.

## CLEAR and CITYSCAPE are a resumable program, not one setup call

The following is the source call graph. Calls listed on one setup path can all execute in the **same** button iteration; they are not exclusive states:

```text
CLEAR button
  clear-all → paint patches white → reset-ticks

CITYSCAPE button: setup
  if setup-done? = true: message, STOP before tick
  tick
  generate-cityscape
    if ticks = 1: generate-topography → services/first builders → towards-other-centers
    first builder movement/write pass → first builder branching/collision pass
    draw first-phase-limit
    second-order builders → third-order builders → remove boundary builders
    refresh values/weights when ticks > 10 and any third-order builders
    if no first builders AND some third builders AND all third energies = 0:
      adjust → maquiladoras
    if any employment centers: STOP this helper
  if any employment centers AND no migrants: initial-condition
  if any migrant size = .65: round patch land values → initial-condition-2
  if third-phase = "go": economics
  if third-phase = "stop": round land values → reset-ticks → setup-done? = true → STOP

GO button: go
  if setup-done? != true: message, STOP before tick
  tick → complete ordered GO procedure below
```

Source STOP sites occur in `setup`, `generate-cityscape`, `adjust`, `initial-condition`, `initial-condition-2`, `economics`, and `go`. The intended nested-helper interpretation is return from that helper, with `setup` continuing; completion only stops the CITYSCAPE host at its final branch. This is strongly supported by the source's own structure and preview (`setup while [ticks > 0] [setup]`), but nested STOP/agent death propagation is still a native runtime probe before translating each STOP into a TypeScript return. A return from `generate-cityscape` must not become an unconditional return from `setup`. A dead agent stops executing its remaining block; later saved activation entries referring to dead agents must be skipped.

CLEAR resets all agents, model globals and fields, paint, source birth ordinal and the World tick; input widgets remain configured. It does not request a random reseed. **No reseed does not prove no random draws:** its `ask patches [set pcolor white]`, source observer reporters and subsequent display asks may advance the native stream. Target CLEAR that preserves the complete Random continuation is an explicit schedule adaptation pending native evidence, not a proved native property. Clear must not replace the retained World/Grid/Random identities just to obtain initial state.

There is no source terminal predicate based on an empty generic builder population, and no finite completion bound. CITYSCAPE may be interrupted between calls and resumed. Every resumed call still runs `generate-cityscape`, including its unconditional normal draw and surviving builders, even after employment centers exist. Equipping, seeding and economics are conditions inside that same call, not mutually exclusive enum branches.

### Cityscape details that affect the later population

1. **Topography:** set every elevation 9.9. Sample `(random 4) + 2` interior nuclei with `abs x < 65` and `abs y < 37`. Three times, for every sampled nucleus: set elevation 8; sample 15 patches in radius `N(15,3)` and set 8; choose one Moore neighbor, set it 8 and sample 13 patches in radius `N(8,2)` around that neighbor. Two passes select patches with more than two elevation-8 Moore neighbors and set 8. Remove elevation-8 patches with fewer than two such neighbors, then diffuse elevation once at rate 1. Predicate snapshots must be taken at each source ask entry; do not recalculate membership after every assignment within the same ask.
2. **Services and first builders:** initialize utilities `(water,electricity,transport) = (10,1,1.5)` and `occupied = "no"`. Sample the requested interior service sites. A site and its Moore neighbors get land 35 and utilities `(2,3,1)`; radius 20 gets elevation 9.9. Sprout one service center, then `round(N(4,1))` builders. Builder label is `who+1`; heading is `N(label × 360 / current count builders,20)`, energy `N(75,15)`, block size `round(N(2,.15))`, weight .9. All births and count timing matter. Assign origin lists afterward and, if the requested service count exceeds one, orient one road per center toward a different center.
3. **First builder pass:** clear `too-close`; move 1; on tick multiples of 20 replace heading with `N(heading,3)`; weight becomes precision(weight−.02,3); write current patch land `12×weight`, transport .75, ctr `"+"`, and radius-8 ctr `"+"`. A separate ask then branches on ticks belonging to `blockSize × [1,3,7,10]`, hatching second builders at ±90° with `random parentEnergy`. Two-ahead outside causes death; two-ahead transport .75 causes forward 2 then death. First builder energy is never reduced in this source.
4. **Second builders:** draw `first-phase-limit = round(N(100,10))` once per call before their ask, even if the set is empty. Each moves .5 when energy differs from zero; changes weight by −.001, precision 3; writes `7×weight` and utilities `(2,3,1)` **before** clamping negative weight to zero. Off-grid/collision checks occur later. Heading correction is triggered by rounded heading mod 15 < 5 or > 10 and adds `round(N(5,10))`. On ctr `"+"`, subtract .5 only if a newly chosen service is within 60. Off ctr, subtract 1 and another 2 if another chosen service is farther than 60. Energy < .5 becomes 0, then energy 0 dies. Check ahead 1 outside, terrain < 9.9 (move .5 and die), land != 0 (move .5 and die), transport .75 (move 1 and die). The later `ticks < first-phase-limit and energy = 0` death is unreachable for a surviving agent because zero energy already died. Still preserve the unconditional normal draw. Finally test `ticks mod round(N(5,1)) = 0` before the `energy != 0` conjunct; hatch two third builders at ±90°, each energy `N(parentEnergy,2)+2`.
5. **Third builders:** newly hatched second→third Agents participate in this later ask during the same call. They move .5 only for nonzero energy, subtract .0007 from weight then precision 3, write `7×weight` and utilities, and supply radius-2 electricity 3 when weight > .3. Clamp negative weight **after** the land write. Heading correction is the same. On ctr `"+"` a random service-distance < 60 subtracts .5; off ctr subtract 1; independently a fresh random service-distance > 60 subtracts 2. Energy < .5 becomes 0; zero does **not** die. Test `ticks mod round(N(3.75,.25)) = 0 and energy != 0`, then hatch ±90° children. Their current ask snapshot excludes these new same-breed children, although they exist for subsequent queries and cleanup. Ahead outside or low terrain dies; road ahead moves .5 then dies; nonzero land ahead moves 1 then dies. A parked zero-energy builder still runs these writes, random modulo expression and collision checks on later calls.
6. **Finalize roads:** remove all three builder kinds whose current *patch* lies on x = ±85 or y = ±57. For ticks > 10 and some third builders, `values = mean(current patch land of third builders)`, `weights = mean(third weights)`. Adjustment requires no **first** builders, some third builders and every third energy zero. It does not require second builders to be gone. Diffuse land seven times at rate 1, clamp negative land, precision 2, recompute the two means at the remaining third-builder locations, copy them to the marginal caches, then delete third builders. If requested service count > 1, assign service size `round(landValue−3)` and only afterward clamp size < 2 to 2. Whether a negative intermediate size assignment errors before that clamp is a native probe, not permission to reorder it.
7. **Employment placement:** candidate land is strictly > .05 and < .75; abs x < 80, abs y < 52; max-neighbor land < .6 (plus the redundant > .015 test); transport != .75, elevation exactly 9.9; a road is strictly within 6, and none strictly within 3. Warn on too few candidates but still create the requested count. Choose a candidate with no job within 5; if none, the new job stays at its default origin (0,0). Its patch receives the **strings** `"0.0"` in water, electricity and transport. Delete colocated duplicate jobs afterward. Only occupied industrial-candidate sites and their two nested Moore neighborhoods get `occupied = "maquiladora"`; an origin fallback that is not a candidate is not marked by this loop. Exact requested count is not a valid final-count invariant.
8. **Initial migrants:** candidate lots are unoccupied, nonroad, > 8.5 elevation, farther than radius-10 inclusion from every job, land ≤ values−.35 and land > values/45, and within distance < 6 of some water-2 patch. Mark candidate ctr `"p-i-lots"`. Let `F = round(equippedPatchCount × initDensity / 6)` where equipped means water = 2 and electricity = 3. Select `F/5` candidates; native fractional/shortage semantics need probing. Each sprouts a .65 migrant, random origin, occupancy origin, a one-element nearest-job `works` list and rounded `N(8,2)` residence. Income, savings and expenses remain their initial zero.
9. **Expansion and economics:** when any .65 migrant exists, choose just one, set it .6, and make four attempts to choose an unoccupied > 8.5-elevation patch in radius 3. `patch-set nobody` is intended to yield an empty ask when no candidate exists; verify rather than calling the ordinary `ask nobody` policy. Each successful child gets .6, random origin, nearest work, rounded normal residence and immediate `get-costs`. The seed parent does not get costs here. Recolor all migrants and write all their occupancy. When no .65 remains set `third-phase = "go"`. Economics can then run immediately in the same setup call; its details below matter. After successful economics sets `"stop"`, round land, reset tick to 0, then set setupDone true.

The source does not automatically call `update-display` during CITYSCAPE. A displayed road can be pen history on a still-white patch. Retain drawing output in a bounded/documented presentation record or explicitly describe its visual adaptation; do not pretend land coloring alone is the original road drawing.

## Economics, GO ordering and caches

For a migrant at its current patch, with one randomly selected service center S and one randomly selected surviving member W of its assigned workplace list:

```text
transportCost = transport × (distance(S) / 30 + distance(W) / 25)
livingExpenses = landValue + electricity + water + 27 + transportCost + 8
```

Food 27 and other utilities 8 are source constants. Infrastructure fields are cost coefficients/categories, not booleans; land prices, savings and income are model quantities without a documented real currency. Division by 30 and 25 uses patch-unit distance. Relocation affordability uses landValue < savings × .0010 and charges landValue / .0010, a different scaling from periodic living expenses. Residence is described as years in Info but incremented once per 15 GO ticks; no year conversion is supplied for road-generation ticks.

`economics` activates migrants sequentially. For each migrant, subtract .5 from every colonia in radius `4 − coloniaSize/2`; get current costs; set global maxCost to **the current maximum expenses over all migrants**, including previously initialized and still-zero/old values; draw and precision-round income `N(maxCost,3)` to two decimals; round its expenses. Thus maxCost can change within this loop, and an agent's income depends on activation order. After the whole loop, for each income < expenses repeatedly subtract 1 from expenses until affordable. This adjusts recorded expenses, not land, utility coefficients, income or savings. No arbitrary zero clamp exists. With finite values and successful arithmetic the final predicate is true and thirdPhase becomes stop. The final maxCost is not recomputed after the affordability reductions.

| GO order after successful setup guard | Observable effect and timing |
| --- | --- |
| 1. Advance World tick | Happens before every operation below, including empty-population failure. |
| 2. Refresh values/weights if third builders exist | Read patch land at their current locations; marginal caches remain unchanged. |
| 3. Set maxCost from migrant expenses | Empty population is an error boundary, not normal successful termination. |
| 4. `update-display` | Includes the colonia scientific mutation below; paint reflects this early point in the step. |
| 5. Round every migrant's savings/expenses | No general get-costs recomputation. |
| 6. `migrate-static` on tick mod migrationTicks = 0 | Select one parent; choose vacant/elevation > 8.5/land ≤ parent-patch land within 1.5. Hatch child and move **child**. The following resets affect the **parent**: occupancy, shape circle, residence 0, costs, income N(55,3), savings N(15,5), costs again, colonia −.5 within `4−coloniaSize`. Child inherits pre-reset properties and workplace. No population-sized wave. |
| 7. Write occupancy; age | All migrants write occupied = origin. Every 15 ticks each residence becomes round(residence + 1), including migrants just hatched. |
| 8. Growth controls | Set third-builder hidden status. If cityGrowth, regulate; if also tick mod buildingTicks = 0, grow-city. If cityGrowth and tick mod (2×buildingTicks) = 0, each surviving third builder hatches right/left copies with marginalWeight. Fractional positive buildingTicks is supported by the widget; do not round it to an integer. |
| 9. Patch and boundary cleanup | Clamp land < 0 to 0; clear occupied only if no migrants and occupied != maquiladora; set colonia > −.1 to 9.9. Delete **all turtle kinds** on the extreme patch rows/columns. This is after their earlier actions. |
| 10. `regularize` | Runs even when cityGrowth is false. May create rings and third builders; therefore cityGrowth false does not imply no builders can be created. |
| 11. `cross` | At crossing interval delete one random migrant, then increment crossed by 1. Info's percentage wording is not the code. |
| 12. `earn-spend` | Each remaining migrant gets precision(savings + income − expenses,2); if savings < 7 set exactly 0, even when negative. |
| 13. `move` | Residence > 5, current water = 10 and savings > requiredCapital permit selection within radius 50 of water-2/electricity-3/affordable land. Face it, jump to it, set red and size .8, subtract land/.0010, get costs. No occupancy exclusion is used for destinations. |

`grow-city` moves .75, subtracts .05 from weight with precision 3, calls get-costs for migrants at the destination **before** changing that patch's land/utilities, then sets land = 3×weight and utilities `(2,3,1)` and adds .15 colonia to that patch and each Moore neighbor. Later land cleanup clamps a negative result, but those earlier migrant expenses remain cached. `regulate` evaluates ahead-1 conditions in order: outside dies; road moves 1 then dies; land higher than current moves .5 then dies; maquiladora dies; no migrants ahead dies; no ring within 8 dies. No later condition runs after death.

`regularize` chooses a patch with colonia < −14−coloniaSize, a migrant on its Moore neighbors, x < 81, y < 53 and no ring within distance < 15. These inequalities are **asymmetric**: no abs is used. At fewer than five rings it sprouts one. Each ring's size becomes `abs(mean(colonia at migrant locations within radius 10)^2) / 3`; the mean is weighted by migrants, not by distinct patches. Rings die if size < 3 or fewer than five water-10 patches occur within radius 8. Without a third builder within radius 6, choose a patch within **radius size**, with `(abs(landValue) − values) < .25`, a migrant, water 10 and no third builder there. This is not `abs(landValue−values) < .25`; it has no lower bound on that difference. Sprout a third builder, weight marginalWeight, face a nearest migrant, origin the spawning Field.

Cached occupancy can remain on a vacated/crossed migrant's old patch until the next GO cleanup. A moved migrant's new patch may not have its origin written until the next GO occupancy phase. Multiple migrants can share one patch; mixed-origin occupancy is the last writer in activation order. Preserve these facts rather than "repairing" the cache whenever an Agent moves.

## UPDATE NOW, ADD NODE and reports are part of the model contract

`update-display` in colonias mode first changes every exact colonia 0 to 9.9. It then colors nonzero colonia > −10 as colonia+10, and colonia < −9.9 black; overlapping tests run in this order. This changes future economics, migration and regularization. It belongs in a public headless `updateDisplay()` action and the explicit early GO phase, never in rendering or `read()`. It is callable before CITYSCAPE and while CITYSCAPE is paused; source UPDATE NOW is not tick-disabled.

Other display modes preserve color memory: off overwrites all white; elevation all elevation+50; land gradient all land values; no-water/no-power only overwrite qualifying occupied cells, leaving other old colors. Color-code paints origins; with color-code off, only circle-shaped migrants become white for the land gradient or black otherwise. A rule edit alone does not execute update-display. Target presentation-only activation can be RNG-neutral by explicit policy, but native asks may draw; do not confuse that policy with native equality.

ADD NODE's widget command is substantive: sprout a node on the clicked patch, set size 3, loop shape/red; set the node patch utilities `(2,3,1)` and land = current `weights`; then for patches within carryingCapacity with occupied != maquiladora and land < marginalValue set those utilities and:

```text
landValue = weights − distanceToNearestNode / carryingCapacity × .15
```

The center is modified before the surrounding predicate is selected, even when its old occupied value was maquiladora. Nearest-node distance uses all existing nodes including the new one; no patch occupancy registry or new graph is implied. Source `display` is host refresh only. Expose one placement per headless action; repeating while a mouse is held is a host policy. Validate target coordinates before any birth or field mutation.

Read-only reports must retain source units and subsets:

| Reporter | Exact source meaning |
| --- | --- |
| irregular settlers | All migrants, including relocated .8 migrants. |
| savings | Mean savings over migrants of **size .6** only. |
| savings node | Mean savings over migrants of **size .8** only. |
| no water | `100 × count(fields with an actual migrant and water = 10) / (equippedPatchCount × initDensity)`. |
| no power | `100 × count(fields with occupied != "no" and != "maquiladora" and electricity = 1) / (equippedPatchCount × initDensity)`. Uses the occupancy cache; unlike no-water, no actual-migrant test. |
| values, weights, marginal, crossed, builders | The source caches/counter and current third-builder count, not freshly recomputed substitutes. |

Both percentages count patches, not people, and use an infrastructure/density denominator, not migrant count. They need not be bounded by 100. Empty means and a zero denominator can make native monitors unavailable while simulation state remains inspectable. A target read must remain pure and readable after a runtime error: expose undefined/error-status for unavailable monitors rather than throwing the entire read or manufacturing zero. Source inspect selects a minimum-income migrant, a random nonzero saver and a random occupied patch; implementing the exact action consumes selection randomness. A deterministic host inspector is an explicit interaction adaptation, not the same source action.

## Reachability and partial failures

| Boundary | What source analysis establishes | What must not be claimed or repaired |
| --- | --- | --- |
| Typed `"0.0"` utilities | Actual strings are unconditionally assigned on each newly created job's current patch, including origin fallback. Type equality differs from numeric 0 and all numeric categories 1/2/3/10/.75. | Do not `Number(...)` or use JavaScript `+` coercion. A faithful numeric get-costs operation must reject a string if reached; exact native error/order needs a probe. |
| Does every run hit that string error? | Initial lots exclude radius 10 around jobs; normal residential seed costs therefore avoid job centers. Valid industrial neighborhoods are occupied maquiladora, which migration rejects. However a fallback origin can remain occupied "no"; migration does not exclude jobs and relocation/growth/node interactions can later overwrite or visit fields. | A string exists does not imply default CITYSCAPE necessarily fails. Reaching its cost operation needs a concrete trajectory or an explicitly diagnostic injected case; do not label the injected case naturally reached. |
| Missing service/workplace in get-costs | Successful normal initialization has ≥1 stationary interior service and ≥1 surviving interior/origin job; works points to jobs assigned after duplicate deletion. Ordinary GO does not delete these interior centers. | A dangling workplace/no-service fixture is a robustness diagnostic, not a demonstrated default-run outcome. Do not silently choose a replacement job or substitute zero distance. |

Approximate floating parity is not a license to move rounding across arithmetic. |
| STOP versus error | Guards intentionally stop before tick; internal STOP expresses control flow; errors abort at an operation after earlier effects. | Do not make every STOP a thrown error, rollback every failed action, or treat errors as successful setup completion. |

For a failed setup/GO operation, the advanced World tick, completed Agent/Field mutations, births/deaths and consumed Random state/cache remain. No history entry may describe that as a fully completed step; retain an explicit failed-action status or let the action throw with an independently readable partial snapshot. A repeated action starts from that retained state and the next tick, not the failed operation's beginning. Invalid **target inputs** are a separate contract: validate an entire rules/fixture/placement request before writes and preserve all state on that validation failure.

The source normal generator and target polar implementation have different stream and activation schedules. The target Random continuation includes its cached standard Gaussian; history/read/failed-action diagnostics must not draw or consume it. Native decimal precision, transcendental values and ask ordering are separate from scientific equation preservation. Document such differences explicitly; never promise same-seed native parity.

## Minimal public model shape to freeze

Follow existing `experiments/definition.ts` and model modules: export typed `inputs`, `create(options = {})` and inert `model satisfies Definition<...>`. This analysis proposes model-local actions; it does not add global APIs to the library:

- `clear()`: source CLEAR state reset, same canonical World/Grid/Random, explicit target RNG policy. Construction returns a cleared model with configured seed, rather than hiding a cityscape loop.
- `advanceCityscape(count = 1)`: validate finite nonnegative integer count; execute at most that many complete source setup calls and stop on completion. If already completed, report the source preflight condition without tick/draw. Do not call a final completed guard repeatedly for a large count.
- `advance(count = 1)`: source GO only; before completion expose the source preflight result with unchanged state/time/RNG. Existing model actions return void, so guard status can be an action result or a readable message; choose one consistently before freezing, rather than silently replacing source STOP with RangeError.
- `setRules(partial)`: source input edits, no implicit recolor/reinitialization. Source controls remain live in paused cityscape/GO at their actual next read sites. Seed is factory configuration; changing it is not an ordinary source slider edit.
- `updateDisplay()` and `addNode({x,y})`: complete headless source actions. `read()` never invokes either. An exact source `inspect()` action can be added if its randomized selection behavior is required by the UI contract; otherwise explicitly expose detached inspectable records and document the host adaptation.
- `read()`: deeply frozen detached Fields/Agents, all scientific caches, setupDone/thirdPhase, World tick, parameters, Random continuation, action outcome/warnings, reports, and explicitly segmented history. Do not equate ready with done: readiness stops CITYSCAPE, while GO has no source successful terminal rule.
