# Graph generators: eleven-kind contract and five example proposals

Status: **proposal only**, 6 November 2026. This is preparation for the existing public `graph.generate` contract, a concrete dependency of selected NW General Examples. Exactly five complete asserted public scripts cover all eleven existing kinds. No generator runtime, public export, configuration, frozen checksum, Git state, delivery ledger or UI is changed. The parent owns final decisions, acceptance/freeze and later scoped implementation. Analysis phase006ccdb is separate and untouched.

## Binding closure and current implementation evidence

[Graph generation](../agent-loom/api-reference.md#graph-generate), the [API operation](../agent-loom/api-table.md#graph-generate) and [GeneratorOptions type](../agent-loom/api-table.md#type-generator-options) already define:

```ts
graph.generate(options: GeneratorOptions<N>): readonly Edge<N, E>[]
```

The exact eleven kinds are **path, cycle, star, wheel, complete, tree, lattice, random, smallWorld, preferential, geometric**. The discriminated union/signatures, option names, defaults and formulas remain the existing reference; no Kleinberg kind, generic plugin registry, fake generator result or renamed public helper is introduced. The examples import the existing public Graph/Edge/Random/Agent/World/Position vocabulary and the binding target type GeneratorOptions. Missing generate/GeneratorOptions exports are expected preparation diagnostics, not permission to weaken the API.

Every generator uses supplied **existing canonical member nodes in explicit author order**, never creates or clones nodes. The selected induced subgraph must initially have no edges, regardless of the requested probability or eventual output. Other regions and crossing edges remain unchanged. No loops are generated. Return the frozen array of newly created original Edge identities, in a deterministic reviewed order, with cloned graph edgeState defaults and no path geometry. The only stated caps are100000 nodes and1000000 generated edges. A selected-node/per-call interpretation is proposed explicitly below; these are not universal live Graph allocation limits.

Source inspection of [Graph kernel](../../src/graph/graph.ts), [Edge construction](../../src/graph/edge.ts), [collection guard](../../src/graph/collections.ts), [state cloning](../../src/agent/state.ts), [Random](../../src/random/random.ts) and [geometry](../../src/geometry/distance.ts) found:

- Graph.add clones its edge-state template and owns membership, edge identities, generated keys and lifecycle hooks. edges.add currently validates/clones/allocates and publishes **one edge at a time**. Its simple-graph path scans existing edges; blindly calling it100000 times is not an appropriate batch strategy.
- There is no public or current internal whole-batch generator/transaction entry. A future implementation must plan and validate the complete batch, including defaults and representation, then commit under one authoritative Graph mechanism. A loop of public edges.add calls with no complete preflight risks partial publication. No new public transaction API is proposed.
- Simple Graph already supports antiparallel directed edges: its duplicate test respects stored direction. It rejects an undirected/directed overlap on a pair unless parallel mode is enabled, but an initially edgeless selected induced subgraph avoids that pre-existing-pair conflict. Do not demand `parallel:true` for all directed generators or wrapped two-cell directed lattices.
- The existing guard rejects structural edits only while its collections are being iterated. Generation must deliberately hold a planning/read guard across callbacks if U3 is accepted; copying nodes then releasing every guard before callbacks does not supply that protection.
- Edge defaults use the shared clone rules, including independent nested containers and preserved framework references. A deleted reference makes a later clone invalid. Automatic IDs and keys are allocated inside construction; rollback/counter semantics are not specified by generate. The proposals check no partial edges and unique original identities, not contiguous opaque IDs or a guessed key-counter reset.
- Random has real continuation/copy semantics and library-issued identity. The proposal uses the current public Mulberry profile as explicit test input; it does not narrow the general generator contract to that RNG forever or claim NetLogo seed equivalence. Generic geometry.distance uses explicit Space; no World context is inferred for geometric generation.

Future implementation belongs in focused graph algorithms and a small state-owner integration. Do not duplicate topology ownership or hide reusable algorithms in an experiment/UI. The binding scalar shape/default-state and host boundaries remain authoritative.

## Existing algorithm contracts preserved

| Kind family | Binding mechanism / exact constraints |
| --- | --- |
| path/cycle/star/wheel/complete | Connect only selected members. directed defaults false; path/cycle follow supplied order, star center first, wheel rim on remaining nodes and outward spokes, wheel requires at least4. Cycle0/1 no edges; cycle2 one undirected edge or two directed arcs. Complete uses every unordered pair, or every distinct ordered pair when directed. Empty path/star/complete valid. |
| tree/lattice | tree root0, child i has parent floor((i−1)/branching), branching defaults2 positive integer; empty valid. lattice shape has1–3 positive integer axes with exact node-count product, x fastest. Face neighbors, wrap false default, collapse duplicate/self neighbor slots. Directed positive-axis steps retain wrap seams. No Grid/World construction or coordinate assignment. |
| random | Visit every lexicographic pair, consume one uniform unit per pair and add iff draw<probability. p finite in[0,1]; endpoints still draw. The supplied Random alone advances. |
| smallWorld | Undirected Watts–Strogatz, n≥3, total neighbors even integer in[2,n−1], probability in[0,1]. Initial ring has neighbors/2 neighbors each side. Visit each original clockwise edge in source/offset order, decide once, then sample an eligible nonself/nonneighbor uniformly if available. Preserve source and edge count; keep edge when no target eligible. Do not replace uniform eligible sampling with a fixed first candidate, an unconstrained endpoint or a biased degree choice. |
| preferential | Undirected, links integer1…n−1. Seed complete graph on first links+1 nodes; visit remaining nodes in order. Each selects links distinct previous nodes with degree-proportional mass, zero-degree mass0, stable cumulative scan, one unit draw per choice. Update temporary degrees after the batch. Never sample uniformly or with replacement as an implementation shortcut. |
| geometric | Undirected; capture each position once in node order; homogeneous finite XY or XYZ, radius finite≥0. Optional normalized dimension-compatible Space; distance≤radius, ordinary Euclidean without Space, explicit topology with Space. No World inference, position mutation, geometry attachment or coordinates fabricated for abstract nodes. |

[Oracle results](graph-generators-proposal-evidence/oracle-results.json) retain exact simple topology/count expectations and small draw ledgers. [verify-oracles.py](graph-generators-proposal-evidence/verify-oracles.py) independently checks cube adjacency with XOR/Hamming criterion,3–4–5 distances, Bernoulli pair thresholds, exact rational cumulative-degree thresholds, manually audited SmallWorld eligible pools and cap formulas. [Existing public Random streams](graph-generators-proposal-evidence/public-random-streams.json) were actually executed separately and matched an independent integer stream calculation. This is existing-RNG evidence and proposal math, **not generator runtime or a statistical uniformity study**. For a uniform unit draw, an index selection uses equal-width intervals in the established Random semantics; arbitrary-cardinality bit-level sampling refinements are not silently given a new RNG/API contract.

## Actual NW protocol and genuine remaining gaps

Use [existing NW audit](selected-host-capabilities.md) and the [local source excerpts](graph-generators-proposal-evidence/source-protocols.json). Original served source SHA remains **9c80d9fa4d5d4da96224e65cd707639267da3f6494309d9d45b758164d2703db**, Galapagos90be931773fcf499049247a8aaa1aecbe003654c, NetLogo7.0.4. Source archive was read locally; no archive refetch, literature sweep or browser run occurred in this task.

Original `generate` optionally calls setup, runs a task that creates turtles/links, lays out **all** turtles/links, then updates plots. It has no tick increment. Target `graph.generate` only joins already created nodes; clear/append, birth/state setup, visual layout and histogram refresh remain explicit model actions. The current selected source has100-node default, can append disjoint groups with clear-before false, uses directed or undirected breed selection and graph lattice wrap independent of hard display boundaries. None of these model actions may be silently replaced by a single library generator call.

It does **not** give the complete normalized probability law, distance metric, shortcut count, candidate exclusions, direction/duplicates or draw order in the consulted section. The model Code/Info contain the call above, not an expanded kernel equation. No pinned extension-implementation revision or new mathematical provenance is falsely claimed.

A future Kleinberg decision must pin the actual extension implementation and its law. A possible family-level contract question can be written `P_r(v|u)=d(u,v)^(-r)/sum_{w in C(u)} d(u,w)^(-r)`, but **this is not a recovered/verified NW equation or accepted API**: d, candidate set C, number/direction of added shortcuts, toroidal distance and exclusions are precisely the missing source contracts. Neither that formula nor the name authorizes a new kind here. No new literature research was performed.
