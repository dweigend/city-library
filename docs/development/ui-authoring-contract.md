# UI authoring contract


Both UI hosts use the same declarations for setup controls, live actions, groups, monitors and charts. The host owns presentation drafts and lifecycle; the model owns scientific state.

## Bounded scope

Typed controls and flat groups keep common author tasks short. Monitor formatters and categorical bar data remain presentation concerns; neither changes model values. There is no layout tree, model wrapper, introspection API or renderer escape hatch.

### Setup and live controls

- `setup` accepts an ordered readonly array of parameter-key strings and existing `{ field, label?, widget? }` override records. A string is the canonical ordinary form; use a record only for a concrete override. Explicit `[]` renders no setup controls. Invalid fields remain type errors and runtime mount errors.
- Canonical `live` is a partial field-keyed object. Each key is a parameter key, with required `set(model, value: P[K])`, optional `label`, `widget`, `enabled` and `group`. Keys render in ordinary object own-key enumeration order. Existing live arrays preserve their scalar-union setters and required `value` callbacks unchanged.
- For keyed live entries, `value(state)` is optional only when every observation has a required, compatible `parameters[K]` whose type is assignable to `P[K]`. Otherwise a field-typed `value` callback is required. Optional/missing/incompatible parameters cannot silently display undefined. An explicit value callback always takes precedence. Reading a live value never guesses a setter or writes the observation.
- With keyed live (including an empty object), omitted setup lists descriptor keys in declaration order excluding live keys. With legacy live arrays or omitted live, omitted setup retains the current all-input behavior, including the duplicate-control compatibility rule and live-reader precedence. Explicit setup always determines its own selection/order. Explicit overlap and legacy omitted overlap have separate setup and live presentation drafts in both hosts. Editing setup changes only its pending draft, never the active model or the live display. Editing live updates its own draft before initialization, and invokes its setter after initialization. The live reader always wins when the next Setup/Restart constructs a model, regardless of edit order; refreshing a live control must not overwrite the separate pending setup draft. These drafts are presentation state, not competing domain owners. Descriptor defaults and validation remain authoritative.
- `group?: string` sits directly on a live entry (keyed or legacy). A nonempty group label renders an accessible fieldset/legend. Groups appear at their first occurrence and collect members in declaration order; ungrouped controls retain first-occurrence order relative to groups. Equal labels mean the same group within one mounted entry. No nesting, collapse configuration or host DOM query. Grouping has no scientific effects. Empty/whitespace-only labels reject at mount.
- Number, boolean and choice setters receive the declared field type without author coercions. Factories/actions still validate runtime values. Before setup, editing live controls contributes to setup only; after setup it calls only the explicit setter. At the DOM boundary, decode against the canonical descriptor before invoking a keyed setter: numbers must be actual finite numbers (not strings/NaN/Infinity), booleans actual booleans, text actual strings, choices actual strings included in descriptor options. Retain the field identity through normalization. Descriptor validation does not prove arbitrary branded, literal-number or refined text TypeScript types; factory/actions remain responsible for those narrower semantics and cross-field constraints. No generic schema framework or unchecked claim of runtime P[K] proof is introduced. Controls read canonical state after actions, and existing pause/completion/disposal behavior stays intact.

### Monitors and charts

- Monitor `value(state)` is a required pure string-or-number callback. Optional formatting changes display text only; the default is `String(value)`. Annotate a numeric formatter `(value: number) => ...` or text formatter `(value: string) => ...`; incompatible getter/formatter pairs reject, including a numeric-only formatter on a genuinely mixed getter. Mixed getters require narrowing. Unannotated formatters retain the `string | number` context. This is explicit scalar annotation, not automatic scalar inference across heterogeneous arrays. `Monitor<S, V>` supports extracted scalar-specific records; `UISpec<P, M>` retains its broad compatibility context. Format errors follow the host error path. The [monitor reference](../ui/api-reference.md) provides public examples.

- Existing numeric `Series` remains unchanged. Export `BarSeries` with the same label/color shape and points `{ x: string | number; y: number }`; only bar views accept categorical x values. Line/scatter remain numeric. A bar view accepts homogeneous numeric or homogeneous string x values across its series; mixed modes reject at render. Categorical positions use first-seen category order across all series. Series are grouped side by side inside each category in declared series order, never silently overpainted or stacked. Duplicate category labels within a single categorical series reject at render; equal categories across different series share a category group. Missing categories leave an empty series slot, without zero imputation. Negative finite y values are supported below a zero baseline; zero values remain visible in accessible labels. Empty series/data render an empty chart without inventing categories. Numeric legacy bars retain their accepted inputs, including signed values; their existing position semantics are not replaced with the new categorical grouping rules. No implicit aggregation.
- Chart views accept optional `xAxis?: { label?: string; unit?: string }` and `yAxis?: { label?: string; unit?: string }`. Omission preserves existing behavior. If label and unit exist, display `label (unit)`; if only unit exists, display the unit. Labels/units and category names are present in accessible chart text. Units are text, never conversion or scientific calculations. No arbitrary tick-format callback or chart-library options.

## Examples and acceptance

`examples/ui-authoring/01-defaults-and-inert-entry.ts` through `05-independent-actions-and-legacy.ts` use real Voting and Wealth Distribution factories. An alternate-observation adapter delegates to the real Voting factory and merely renames the observation's parameters property; it contains no simulation substitute. Bun executes real model actions, callbacks and assertions. Exported browser checks mount the same public entries into a caller-supplied real DOM container. Their execution is separate required browser evidence, not inferred from Bun checks.

Compile `examples/ui-authoring/tsconfig.json`, including negative compile-only cases. Execute all five scripts with assertions enabled and verify SHA256SUMS. Browser acceptance must additionally verify actual setup order/default exclusion and legacy overlap, keyed implicit/explicit getters, numeric/boolean input changes, accessible flat grouping, formatted monitors/category and axis text, independent mounted entries and stale/disposal behavior in both supported host adapters. Preserve supported light/dark and desktop/narrow screenshot gates. No mock DOM or public test-only introspection API is permitted.

Passing headless callbacks does not establish control normalization or browser acceptance. Changes to accepted expectations require an explicit recorded reason; implementation convenience is insufficient.
