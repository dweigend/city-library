## Giant Component

Source defaults: 80 nodes; num-nodes 2..500 integer, setup-only; no edges at setup. Nodes initially circle-layout in a 91×91 hard view; layout? defaults true. Setup, go once/forever, redo-layout forever and layout switch are the relevant controls. The monitor is largest component size. Plot x is **2E/N connections per node**, y is **largestSize/N**, with a separate static vertical reference at x=1. It is not a tick-indexed curve.

Go preflight stops only when `2E >= N(N-1)`, the complete simple graph, and displays a user message. Having all nodes in one connected component is **not** termination. Each successful go adds exactly one missing undirected edge. It repeatedly samples **two independent uniform existing nodes**, rejecting self-pairs and existing links. Do not sample one node then uniformly one of its missing neighbors: that changes edge probabilities. The recursion may become an iterative rejection loop without changing accepted-pair policy. Recompute components/giant highlight, recolor links from end1, optionally layout only while not every node is red, then tick. No node births/deaths or duplicate/self edges.

Important code/Info distinction: `giant-component-size` and `giant-start-node` are not reset by find-all-components. A strictly larger discovered part replaces the stored anchor; an equal-size part does not. Thus when maximum size does not increase, the previously highlighted giant remains highlighted. The Info's statement that ties choose a random component is an incomplete summary. When the maximum increases, randomized component exploration determines the first new maximum among ties. Highlight differences are presentation only, but must be declared; largest size/fraction, topology and terminal behavior are functional. Component queries themselves should be pure, with any deliberate highlight-selection randomness in the model procedure, never read/render.

Proposed parameters: `numberOfNodes` default80/min2/max500 and seed. `read`: tick, parameters, nodeCount, edgeCount, giantSize, giantFraction, meanDegree, nodes(id,index,component membership/highlight), edges, history including meanDegree/giantFraction, randomState, done, stopReason `complete` or null. Public component algorithms supply groups, never model-private search. Current stop status may report complete immediately after the last successful edge; a later advance adds no tick. Shared UI status replaces the source modal stop message explicitly. The setup singleton largest size is1, not0. N=2 setup has giantSize1/fraction.5; one go yields E1/giantSize2/tick1 and is complete. No Giant runtime/frozen model script is delivered by this audit.

## Virus on a Network

Source defaults/bounds: number-of-nodes150, 10..300 step5; average-node-degree6, 1..N-1 integer; initial-outbreak-size3, 1..N integer. These apply at setup. Live virus-spread-chance2.5%, 0..10 step.1; recovery-chance5%, 0..10 step.1; gain-resistance-chance5%, 0..100 integer; virus-check-frequency1 tick, 1..20 integer. No fabricated 100%-recovery slider or scientific rescaling. Setup and forever go; all three plot pens are **percent of actual nodes** (susceptible, infected, resistant), not counts despite a loose Info sentence.

Setup creates N canonical nodes at independent uniform x/y within 95% of the source random coordinate range of the 41×41 hard world: each axis `[-20.5,20.5)*.95`. Each starts susceptible with timer integer random(frequency). The simple undirected network grows until E >= averageDegree*N/2; when odd, this means ceil(N*averageDegree/2), so realized mean degree can exceed the slider slightly. Repeatedly sample one node uniformly and connect it to the **nearest unconnected other node**; ties are chosen randomly as min-one-of, saturated sampled nodes add no edge. Then source runs ten spring layout passes. This layout must not retroactively change generation distances/topology. Infect a uniform initialOutbreakSize subset after constructing the network; no node becomes resistant initially.

Go stops before any timer update when no node is infected. Otherwise first increment **all** timers, resetting any >= current frequency to0 (live lowering takes effect here). Freeze nodes infected at spread-phase entry, activate them randomly, and visit each sender's nonresistant neighbors randomly. Every such neighbor, including already infected neighbors, receives an independent random-float(100)<spreadChance trial. New infections do not become additional senders during that same spread phase. After all spread, select the **current** infected nodes with timer0; this includes newly infected nodes. Each independently checks integer random(100)<recoveryChance, and only on recovery draws another integer random(100)<gainResistanceChance to choose resistant versus susceptible. Becoming infected leaves timer unchanged; resistant is permanent under the source's normal rules. Resistance darkens incident links for display. Tick after both phases; extinction during a successful go still ticks once, next call stops.

Proposed parameters: `numberOfNodes`, `averageNodeDegree`, `initialOutbreakSize`, `spreadChance`, `recoveryChance`, `resistanceChance`, `checkFrequency`, seed, with source defaults/bounds/steps above. Validate dependent setup maxima atomically (outbreak<=N, degree<=N-1). Target `setRules` admits exactly the four live fields; validation failures preserve state. It does not remap timers or create infections immediately. Source can make the setup sliders inconsistent live with already-created population; target setup-only treatment avoids that inconsistency explicitly.

Read: tick, parameters, nodes(id,index,x,y,status susceptible/infected/resistant,checkTimer), edges, counts with the three disjoint states, percentages, history, randomState, done. Counts always sum to N. Source-generation positions remain canonical model data; renderer layout is independent. A deterministic `setStates([{status,checkTimer},...])` intervention supplies exactly N valid records, timer integer0..19, preserving graph/positions/IDs/tick/RNG and replacing same-tick history; timers above the current frequency are permitted because changing frequency live can produce that legitimate state until the next go. A deterministic `setConnections([{from,to},...])` replaces undirected edge membership over stable node indices, rejecting self/duplicate unordered pairs and invalid indices atomically. This is an additional public fixture, not an original widget. Existing source recovery/spread bounds remain intact for real controls and fixtures do not fake an RNG algorithm.

Source RNG versus target adaptation: use explicit Mulberry generation/simulation draws, random snapshot activation for spread/check phases and random exact-minimum ties. Omit appearance-only initial headings, spring-layout randomness and order-independent timer-phase shuffles, with these omissions declared. Recovery still uses an **integer** random(100) comparison against possibly fractional recoveryChance, so, for example, positive0.1% accepts the integer0 outcome and has1% effective recovery probability under that discrete source draw, not0.1%. Do not replace it with random-float to make the UI label look more intuitive. Spread uses a continuous draw. This source quantization is functional baseline behavior, not a scientific correction made silently by the port.

## Diffusion on a Directed Network

Source defaults/bounds: grid-size9, odd3..19 step2; link-chance50%, integer0..100; diffusion-rate10%, integer0..100. Grid-size/link-chance are setup-only; diffusion-rate is live. Source view21×21 hard; setup, forever go, rewire-a-link and keep-rewiring controls. Go has **no terminal rule**, including all links inactive or zero rate. Histogram is the current node-value distribution, range0..ceil(maxVal+.5), bins ceil(sqrt(N)); not a time series. Source node size is `.1+5*sqrt(val/totalVal)`; style is a projection, not storage of value.

Setup creates gridSize² nodes on the source centered square patch subset, value1 each. For every ordered face-neighbor pair create one canonical directed edge (both orientations of each undirected adjacency exist). Each edge has currentFlow0 and independent active state: deactivate when random-float(100)>linkChance. Therefore equality stays active; at linkChance0 the finite RNG's exact zero draw is an exceptional active outcome, rather than an unconditional empty graph. Tests needing no active edges must use an explicit fixture. Candidate count is4*g*(g-1), e.g.288 for g9. Source positions are then scaled to ±9 at outer node centers; keep topology from public Grid face-neighbors, not a model-private neighbor/index library.

Go resets every newValue accumulator to0; all old values remain unchanged during transport. For each sender's active outgoing recipients, retain val*(1-rate/100) and split the remainder equally among recipients. With no active outgoing edge, retain all val. Add incoming contributions to recipients' scratch accumulators, writing each active edge's currentFlow to its sent amount. Finally commit all node values, update globals/appearance, then tick. Total value is conserved within floating tolerance; directed sinks accumulate, and inactive edges' previous currentFlow values are **not reset** on each go. Active/inactive is state on the same canonical edge, not duplicated graphs/topologies.

Rewire only if there is at least one active edge: choose one active uniformly, deactivate it, then choose uniformly from the entire now-inactive set and activate it. The just-deactivated edge is eligible, so rewire may be a no-op. Active edge count remains fixed and currentFlow belongs to each edge across switches; never reset it merely because active changes. With zero active edges the action consumes no random draws. Source updates maxFlow/meanFlow only in update-globals after setup/go, and only if active edges exist; rewire itself does not refresh those globals or node values. View appearance may refresh more clearly, but source flow/staleness semantics must be explicit. Keep-rewiring is a host cadence executing this same headless action, independent of model go/tick; it requires real browser verification, not an automatic hidden simulation timer in core.

Proposed parameters `gridSize`, `linkChance`, `diffusionRate`, seed. `setRules({diffusionRate})` is live, atomic and same-tick. `rewire()` performs exactly the above action without tick/history insertion. `setValues(values)` supplies N finite nonnegative values and preserves tick/RNG, refreshing current same-tick quantities/history; total0 is allowed with a declared finite visual-size guard. `setActiveLinks([{from,to},...])` supplies a unique directed subset of the existing candidate edges (reject noncandidate/self/out-of-range/duplicates atomically), changes active flags and resets flows to0 as an explicit deterministic fixture; it preserves identities/tick/RNG and updates same-tick observations. This fixture reset differs deliberately from normal rewire. Tests compare rewire identity/flow preservation separately.

Read: tick, parameters, nodes(id,index,x,y,value), edges(id,from/to indices or IDs,active,currentFlow), counts `{nodes,candidateLinks,activeLinks}`, totalValue,maxValue,maxFlow,meanFlow, current histogram, history, randomState, done=false. The proposed public read includes edge endpoints as node **indices** in `fromIndex/toIndex` in addition to canonical ID fields `from/to`, so deterministic fixtures need no opaque ID parsing. Node indices follow x-fastest Grid.fields order. Edge array order is stable source/target node order; querying/filtering canonical edge snapshots is permitted and does not constitute a second writable topology.

Source RNG versus target adaptation: source ask activation order consumes randomness even in mathematically order-independent reset/transport/commit phases. The target may use insertion-order deterministic transport, consuming **no RNG on go**, as asserted by the proposed public script. Summation roundoff can therefore differ; conservation and known fixtures use an explicit numerical tolerance where nonbinary fractions occur. Setup uses independent Mulberry draws for each candidate arc in deterministic source/target order. Rewire retains its two random selections. These choices preserve the specified stochastic construction/action mechanisms without promising NetLogo seed trajectories or bit-identical floating accumulation.

## Proposed example inventory and sequence

1. Directed 3×3 line fixture: `[8,0,...]`, active arcs0→1→2, rate50. After one tick values[4,4,0]; after two[2,4,2]. This catches in-place cascading and degree-independent duplication; total8.
2. Directed no-active fixture: rewire is RNG/tick no-op; go still ticks and retains values. A two-active fixture preserves active count, all edge identities and pre-rewire currentFlow on rewire (even if the same edge reactivates).
3. Virus timer phase:10 infected nodes, checkFrequency3 and zero spread/recovery, all timer2 => next tick all timer0, infections unchanged. Replacing all states susceptible preflight-stops without tick/RNG; restoring infected resumes. Updating frequency alone leaves timers unchanged until next go.
4. Atomic fixtures/rules: duplicate/noncandidate links, malformed state lengths and unsupported rule bounds reject without state/RNG changes.
5. Exact source defaults and independence: Virus150/450edges/3infected; Directed81nodes/288candidateEdges/total81; setup repeatability excludes process-local IDs; read snapshots detached; two independent models.
