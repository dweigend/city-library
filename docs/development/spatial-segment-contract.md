# Spatial trace presentation

A model can expose its movement history as line segments without asking the renderer to reconstruct it. Tijuana supplies the first use case: its headless observations contain ordered trace endpoints, numeric colors and source pen widths. This contract adds the shared presentation data and drawing rules; movement and time stay in the model.

Public examples under `tests/ui/ui-segments/` cover public canonical movement projected as history, trace survival after Agent deletion, source-palette projection, cells/segments/agents together and legacy/empty/zero-width data. These scripts assert public data authoring and domain purity; they **do not execute a DOM renderer**. Actual rendering, layering, visibility, resizing and theme acceptance require separate Chromium pixel/screenshot checks.

The exported readonly SpatialSegment has with from/to finite two-dimensional world-coordinate points, optional color and optional width. SpatialData accepts optional readonly segments. Endpoints use the same centered model coordinates as cells/agents. Width uses CSS pixels, matching existing symbol-size presentation; default1, zero omitted. Model adapters map headless trace numeric colors through public indexedColor and pass widths through; this declared presentation scaling is not a scientific distance conversion. Missing color uses white. Source traces themselves retain source values. Existing GridData/SpatialData without segments remain compatible.

Draw cells first, ordered segments second and Agents/selection/labels last. Use the shared canvas world-to-buffer projection and CSS-pixel device ratio, without moving or inspecting live Agents. Do not silently discard stored nonzero segments. A stroke renders even after its source Agent dies. Respect zero width explicitly because Canvas ignores assignment of lineWidth0. Resize/theme rendering and disposal preserve existing interaction behavior. No mandatory wrapper, custom model canvas or UI-owned simulation state is introduced.
