## Implementation and provenance

The focused `src/geometry/planar/` files separate public types, exact predicates, shape/topology validation, containment and bounds traversal. They reuse existing `position(value, 2)`, `finite` and `validateOptions`, preserving canonical Agent/Field queries and existing option rules. No host I/O, live identities, clocks or RNG are used by the new kernel.

The original binary64 bit pattern is decoded into an integer multiple of `2^-1074`. Orientation subtracts and multiplies these integers exactly; segment contact uses exact orientations with numerical endpoint bounding boxes for pruning. The existing internal graph dyadic-cost representation was inspected as an in-repository numeric candidate; geometry keeps its own small domain-local decoder rather than depending on graph costs/rounding. No third-party implementation was copied and no dependency or notice was added. Existing bounds/map only provide envelope/affine operations and cannot supply topology. External float/epsilon point-in-polygon or area-only replacements would not satisfy the accepted cancellation/subnormal/contact witnesses; the completed advisory and accepted closure already authorize the focused exact implementation. This task did not repeat research or request another review.

Ring validation rejects zero edges, absent exact closure, collinearity, adjacent overlap/backtracking (including the closure seam), and any forbidden nonadjacent contact. Forward collinear subdivisions remain valid. Complete shell/hole and hole/hole edge contact checks precede strict interior witnesses; both containment directions are checked between holes. This rejects concave bridges whose vertices alone look internal. Classification checks boundaries first and then uses half-open parity crossings without division. Winding has no effect. Include is the default for both exterior and hole boundaries.

Recognized geometry/wrapper fields are read only through own data descriptors on Object/null-prototype records. Dense coordinate/collection arrays reject extra keys, accessors, symbols and holes; array subclasses are allowed. Unused metadata and foreign values are not read, even if they are getters, cycles or otherwise unsuitable for a future codec. Bounds validates necessary geometry only and makes no metadata-validity promise.

Contains validates every ring, including for outside queries, with at most 2048 closure-inclusive positions across the whole Polygon and magnitude at most `1e9` for polygon and query coordinates. Bounds inherits none of those or codec limits; it accepts finite extreme coordinates, larger polygons, more than 10000 features and more than 100000 positions. MultiPolygon members/features may overlap. Every Polygon still validates completely before a result is returned. Bounds results are detached frozen tuples, or undefined without coordinates.

GeometryCollection traversal uses an explicit stack and per-call active/completed sets: active-path cycles reject, completed DAG aliases are allowed, and no recursion or numeric depth/node cap is imposed. There is no cross-call identity-validity cache. Mutable inputs are revalidated on each call, including invalid-to-valid recovery.

## Costs and actual measurements

For a Polygon with `n` total closure-inclusive positions, validation is worst-case **O(n²)** exact/contact work across self-edge and inter-ring comparisons; classification is O(n). Numerical bounding boxes prune segment pairs but do not remove the worst case or change input coordinates. For bounds, cost is O(features + collection references + positions + sum of each Polygon's squared size); shared Geometry objects are completed once per call. Memory is linear in the traversed collection/feature references and current Polygon positions. Exact integers occupy at most about 2098 bits per finite coordinate, with larger exact determinant intermediates. There is no covert resource cap, simplification or repair. Unbounded bounds inputs can therefore require substantial time and memory.

[Raw measurements](planar-geometry-runtime-evidence/measures.json) retain all seven sequential wall-clock samples per case, including the first sample, on Bun 1.4.2 in this worktree. Medians: Russia 1282-position contains 8.22 ms / bounds 8.21 ms; West Bank 11-position contains 0.022 ms; Canada 3316 positions in 126 members bounds 10.90 ms; rectangle at containment cap 2048 positions 6.89 ms; uncapped 2049-position rectangle bounds 6.79 ms; 100001-position MultiPoint bounds 101.91 ms. These are observations on this machine, not acceptance thresholds or universal performance promises. Reproduce with `bun docs/development/planar-geometry-runtime-measures.ts`.
