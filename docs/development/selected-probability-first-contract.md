# Birthday, Galton, urn and probability model contracts

These models introduce no new City Library capability or UI contract. Their named TypeScript procedures compose the existing public `Random`, `World` and `run` API; `create` performs the original Setup, `advance` calls Go, and `read` returns detached, frozen observations without advancing time or RNG. The world is the sole tick owner, local model records own their domain values, and UI adapters call only exposed actions. Importing modules does not create instances.

The exact selected identity remains the original catalog path. Source bytes, full notices, widget inventories and hashes are retained separately in `models/<slug>/source.nlogox`, `NOTICE.md` and the selected models ledger. Scientific dossiers describe assumptions and limitations; they do not establish browser, technical or empirical acceptance.

## Procedures and observed quantities

Birthdays retains `makeMonth`, `makeTurtles`, `sortTurtles`, `showMatches` and `go`. Setup creates no people and constructs exactly 365 named dates, without February 29. Each completed tick replaces the room with 23 independently assigned birthdays, sorts by day, marks every person with at least one matching person, and increments successes at most once. Success rate is successful rooms / ticks, expressed as percent. At tick zero the target displays 0%, an explicit safe presentation for the original monitor's uninitialized/zero-denominator state. A table replaces turtle labels; the dates, ordering and match flags are directly visible. The accumulating success-rate chart is an additional observation.

Galton Box retains the actual lattice and individual particles, rather than replacing the simulation with a binomial draw. `propagate` constructs the distinct peg patches from the original recursive geometry. The inclusive stopping test produces `numberOfRows + 1` peg levels, including the top level; this source behavior is preserved. `counter`/`yellowAt`, `timeForNewBall`, `newBall`, `full`, `doneFalling`, and `fall` retain their patch conditions. `prepareGo` performs the source Go preflight exactly once: release a ball if allowed, discard falling balls above the counters if full (and decrement balls), then stop without a tick if none remain. Go randomizes the falling-ball activation order, bounces horizontally when the patch below is a peg, otherwise descends one patch and changes group at the floor or above a pile. Only still-falling balls currently on counters increment their counter; no-pile mode removes those particles. Read exposes created balls, falling/piled particles, peg positions, counters, full and done. The spatial view and counter histogram replace the source's counter labels and decorative peg colors.

Binomial Rabbits retains captured hop/ratio arrays, `setStep`, `hopping`, `plotViolet`, `plotYellow`, and `goOneHop`. Setup creates the original number of rabbits at zero and captures three slider-provided alternatives, with the fourth and fifth slots zero. Every hop chooses a step through the original cumulative `<=` comparisons, adds the unscaled displacement, and computes the displayed coordinate with the original width-45 wrapping and current xScaling. All-zero ratios preserve the source's first-hop choice, because the zero draw satisfies its first `<= 0` comparison; no invented validation silently changes that behavior. The mean uses unwrapped displacements, histogram counts use wrapped patches, and yScale follows the original normalization. Go stops only when `ticks = hops`, not `ticks >= hops`. Thus explicitly invoking goOneHop after reaching the limit moves beyond equality and permits Go again; this surprising source behavior is tested and preserved. The source Info describes an obsolete manual five-hop `setup` signature absent from the served Procedures; the target implements the actual three-slider setup. Number is setup-only in the target, preventing the source's live denominator/population mismatch. The histogram and mean/scale monitors expose the original quantities; decorative green/violet reference columns are represented by the zero origin and explicit mean monitor rather than reconstructed patch overlays. Rabbit glyphs use the existing circle renderer.

Three Doors retains one persistent racer per person, per-racer switching hunches, the informed host rule in `makeChoices`, `doSwitch`, and `awardPrizes`. The compact host rule is equivalent to the original nine prize/guess cases: if the first guess is wrong, the other closed door contains the prize; otherwise choose either remaining door uniformly. The full source chooses a fresh prize and first guess for every racer on every tick. Each Go randomizes the racer order. Once the first racer reaches y = 35, subsequent racers still perform their choices that tick but cannot move, preserving the original global done gate inside the ask. The completed tick is counted, and later advances stop without another tick. Hunch shading and the race position retain their meaning; an extra scatter view exposes wins by switching tendency. Heading glyph and exact gray palette are presentation adaptations. Higher switching hunches remain darker; the target gray floor is100 on the shared dark canvas so these racers remain visible. Coordinator visual inspection corrected an initially reversed shade mapping before acceptance.

Stochastic Patchwork retains the centered odd-sided block, `go`'s independent draw for each participating patch, latest-first percentage samples, and frequency histogram. Setup's block is neutral until the first draw; the startup-only checkerboard is not a trial and is not substituted for Setup. Frames are represented by the existing grid-cell boundaries. Target count is the current number of green cells, whereas histogram x values are percent green per trial. Probability changes are live and retain all earlier sample history. The source's target-color-is-zero stop is unreachable through its served controls (target color is always NetLogo green); no new user control is introduced for it. Histogram bars aggregate the exact sample percentages; the existing neutral chart renderer supplies its own axis scaling.

## Shared differences and boundaries

Target RNG is public Mulberry32 with an explicit seed; NetLogo uses a different RNG and consumes additional draws for agent creation, display defaults and ask ordering. No same-seed cross-engine trajectory identity or statistically validated distribution equivalence is claimed. Within-target replay at the same seed is deterministic. Complete-agent activation uses the public fisher-yates-descending sampling option, which shuffles references without duplicating domain ownership. Models use no pending Graph capabilities.

The target validates finite numeric/range/integer inputs using the existing descriptors and rejects negative/noninteger/out-of-budget advances before mutation. Source wait/display calls affect host pacing rather than scientific state and are replaced by the existing Play/Pause host. Target Setup/Reset creates a new canonical instance; Step advances the same procedures. Existing controls remain native and accessible through the shared UI shell. Original notices remain accessible through source links and versioned notice files.
