## Diagnostics, design review, and remaining work

This is a scoped review, not certification of complete WCAG compliance, all contrast ratios, every input modality or assistive technology.

Two concrete UI findings remain for the coordinator; this evidence-only assignment did not alter UI code:

- **Medium, `ui/views/chart.ts:98–105`:** a bar/scatter chart's accessible name describes only the last point of each series. The Wealth current histogram at tick9 is announced as `People · low / middle / high: 25`, although its three classes are 149/76/25; a reader does not get all bins. Preferential degree bins have the same limitation. Supply a complete discrete-series text alternative or accessible data table. Actual rendered/ARIA evidence is in [target diagnostics](reference-refresh-evidence/t-diagnostics-bounded.json); source inspection identifies the implementation site.
- **Low, `ui/compose.ts:270` (live controls inserted before monitors):** at 1280×800, Wolf/Wealth tick/population/inequality monitors fall below the first viewport after the live parameter list. The progress screenshots therefore require scrolling plus their checkpoint readbacks for counts. Keep key reporters closer to Run/Pause. Mobile already places monitors before the view and live controls; the mobile captures verify that behavior. This is a usability limitation, not missing model state.

[Source diagnostics](reference-refresh-evidence/source-direct-diagnostics.json) retain the console history across the four source loads. To avoid the launcher's huge catalog accessibility tree hiding diagnostics, the source tab was finally navigated to the official standalone `/web?url=...` entry for the same Wealth Web file; this was a new initial session, not relabeled as the earlier progressed session.
