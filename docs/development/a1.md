## Supported-data and lifecycle invariants

Implement the complete supported-data rule for accepted creation/copy, not a JSON clone. Accept finite scalars (including preserved negative zero), undefined, null, boolean, string, bigint; plain own-string-keyed records, sparse arrays, Map, Set, valid Date, valid RegExp/lastIndex, ArrayBuffer and ordinary non-shared TypedArray/DataView. Preserve cycles, aliases, sparse holes, bytes, view offsets and shared backing identity within each copy; independent creations/copies get fresh ordinary containers. Retain live delivered framework identities, never recursively clone or implicitly register them. Deleted framework references reject.

Reject symbol keys, accessors, functions, extra named array properties, nonfinite ordinary numbers, invalid dates, malformed RegExp lastIndex, weak collections, Error/DOM objects, unsupported custom prototypes, shared/detached buffers and active resources. Validate before publishing objects. Proxies remain unsupported caller inputs; propagate access failures without publication. `structuredClone` alone cannot preserve framework identities or enforce the complete contract.

Reserve exactly the target Agent root keys: id, alive, world, x, y, z, heading, pitch, roll, copy, delete, move, rotate, distanceTo, directionTo, neighbors, canMove, gradient. Reserve no additional state key. Nested names are unrestricted by these root reservations. Use safe own-data definitions for valid names such as `constructor` and `__proto__`. Copy follows current custom state, so unsupported values introduced by later assignment reject at the next clone boundary.

Keep ownership and deletion in a single private protocol with an acyclic dependency direction. Prefer small functions and native collections; no universal manager, second identity registry, placeholder graph hooks or new public plugin protocol. State snapshot rules belong to the Agent domain until another real consumer demonstrates a narrower shared boundary.
