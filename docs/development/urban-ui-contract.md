# Urban model presentation closure

Urban Suite models need two shared presentation controls: painting centers in a spatial view and letting observations decide whether energy labels are visible. Both belong in the UI host. The models still own their centers, energy values, rules and time; the host only projects observations and routes actions.

Compile-only cases in `ui/urban-authoring.types.ts` check the contract. SpatialData accepts optional `showLabels: boolean`: when supplied, the current observation controls label visibility and the redundant host Labels checkbox is hidden. When omitted, preserve the current UI-owned initially-off checkbox behavior. Label text remains authored renderer data. Drawing applies to spatial views with cells as well as grid views. Optional `drawing.toggleLabel` supplies a per-mounted-instance host toggle, initially off, gating drawing in addition to `enabled(state)`. Without toggleLabel, preserve existing Life behavior. Reset/model replacement/disposal turn this host mode off and end any captured stroke; no module-global state or model flag is invented. Toggle actions do not tick or consume model RNG. Reuse existing pointer/keyboard intents; Awareness begin/move call public placeCenter, end has no domain action. UI does not compute awareness/contact/resource/pollution rules.

Thin adapters in experiments/urban-suite-*/ui.ts project canonical observations into the existing spatial cells/agents, inspector, monitors and history charts. Pollution trees and people must remain distinguishable, with scalar pollution and power plants visible. Awareness original/created centers differ purposefully and peer categories remain inspectable. Recycling maps showEnergy to showLabels and supplies preformatted energy labels; live cap/seeking/regeneration/cost call only public setRules. All original setup/live parameters and brush actions remain reachable. Reuse the existing compact visual system; frontend-design then web-design-guidelines apply. No physics or extra population cap in UI.

Required executed browser acceptance per model remains paired pinned NetLogo/target setup/progress and native controls, appropriate desktop/mobile light/dark, inspector/brush/labels, console/runtime diagnostics and explicit RNG/functional deviations. Shared lifecycle tests complement actual browser cleanup checks; no source-only approval. Independent review remains part of acceptance.
