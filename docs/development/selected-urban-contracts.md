## Shared core capabilities

The reviewed implementation surfaces are `index.ts`, public `Agent`, `World/run`, `Grid` and `Random`, the existing Voting and Segregation compositions, `models/parameters.ts`, and the binding DESIGN/PLAN contracts. No new reusable domain capability is needed for these three models:

| Mechanism | Actual public closure and composition boundary |
| --- | --- |
| Toroidal continuous pedestrian motion | `World.add(space,{random})`, `Agent.add(state,{position,orientation})`, `agent.move(1)`, `agent.rotate(angle)`; rotate is clockwise heading, so source left is negative. |
| Patch state and Moore adjacency | `Grid.add(space,{state})`, `grid.fields`, `grid.fieldAt(agent)`, `grid.neighbors(field,{neighborhood:"moore"})`. Field x/y centers belong to Grid; no private cell-coordinate/topology engine. |
| Same-cell conversations and occupancy | Attach Grid to World and call `grid.agentsAt(field)` using canonical current agent positions. Filter the returned snapshot for the appropriate kind/status; no second occupancy authority. |
| Random activation, one-of, n-of, integer/continuous trials | `Random.add`, `random.sample(source,{count})`, `random.number()` and explicit `Math.floor(draw*n)` for source integer trials. Snapshot participants at each source ask entry; sample for order where outcomes depend on it. |
| Births, hatch, death | `agent.copy()` preserves heading, position and typed state; then explicitly set newborn health/kind and `world.add(child)`. `agent.delete()` removes canonical membership. Store kind as ordinary typed model state, not a parallel breed registry. |
| Pollution diffusion | `grid.diffuse("pollution",{rate:0.8,neighborhood:"moore"})` is simultaneous conservative eight-direction diffusion. Do not use its faces default. |
| Reports and histories | Pure reductions over canonical state, then detached frozen records; no missing generic statistics API is required for these sums/means and model-specific thresholds. |

These three models need no graph/component operations. No routing, discrete event engine, Gaussian RNG, extension, external asset, host I/O or separate library runtime is required. Model-specific ecological equations and threshold rules remain explicit named headless procedures, not a reusable hidden simulation framework. If implementation discovers a genuinely reusable missing operation, stop and specify a separate public library phase with four/five asserted examples before implementing it; do not hide it inside a model.

## Shared authoring contract

Each `models/<slug>/model.ts` exports `inputs`, `create(options={})` and `model` satisfying the existing `Definition` contract. `create` returns `advance(count=1)`, `read()`, the listed `setRules` and intervention functions. Public examples define required syntax and behavior.

Each instance owns exactly one World, one attached Grid and one Random. World agents own position/orientation/kind/individual state; Grid fields own land state. Source-specific activation lists are temporary snapshots of canonical references. No persistent writable population/occupancy copy or independent tick. Procedures are named ordinary TypeScript (for example `wander`, `informOthers`, `createCenters`, `expireCenters`, `reproduce`, `plantTree`, `cleanup`, `processRecyclerPatch`, `processWastefulPatch`, `movePeople`, `regenerateResources`). Read is pure and consumes no RNG.

Fixed native dimensions and topology are retained, without speculative width/height inputs. Target coordinates use centered City Library coordinates. Pollution and Recycling already have centered integer cells. Awareness source x=0..36/y=0..37 maps by subtracting18/18.5 to target x=-18..18/y=-18.5..18.5; **Awareness cell y centers are half-integers**. Translation is an observation/input adapter, not another position store. Continuous positions occupy the centered half-open torus `[-width/2,width/2) × [-height/2,height/2)`. User-facing source-coordinate labels may add back the fixed offset transparently.

All inputs use existing `parameters` validation: finite values, source bounds/steps, reject unknown keys and malformed plain-data records. Seed default1 is the explicit target addition, integer -2147483648..4294967295. Setup inputs take effect by creating/resetting an instance. `setRules` accepts only each model's live fields, validates the entire update before mutation, changes no tick/RNG, and applies on the next relevant phase. Existing state is not rewritten to look as if setup had run. An invalid advance count or intervention preserves state/RNG/history atomically.

`read()` deeply freezes detached records/arrays: `tick`, `width`, `height`, `parameters`, `people`, `cells`, `counts`, `history`, `randomState`, `done`; Pollution additionally `trees`, `totalPollution`; Awareness additionally `meanAwareness`, `meanNonUsage`; Recycling additionally `landPercentages`. People records have `id,x,y,heading` and model state; cells have `id,x,y` and model land state. No canonical Agent/Grid references escape. History records setup plus latest1000 ticks using existing repository convention, same-tick interventions replace the latest measurement. Record measurements after a completed tick; no source-style hidden plot callbacks mutate state. Setup/reset recreates a new instance rather than resetting identity in-place.

Interventions are explicit deterministic **target additions**, not original widgets. They preserve tick/RNG, validate completely before mutation and refresh current measurement/history. Replacement people/trees create new canonical IDs; list order determines the subsequent stable observation order. Read order follows canonical World/Grid insertion order; no string-ID parsing. Position inputs must be finite and inside the half-open torus; heading finite and normalized by Agent. Numeric state must be finite. Lists may contain multiple people/trees per patch. Replacing land preserves field IDs. Do not impose an artificial pollution population cap to accommodate the UI.

## Awareness: source mechanism and contract

World37×38, both axes wrap. Inputs: `people`60, 0..300 step10 (setup); `centers`20, 0..100 step5 (setup); `nonUsageLimit`100, 0..500 step5 (live, ticks). Setup creates people, source random headings, gray color, awareness0; source asks each to walk `random25` and then overwrites position with uniform continuous random-x/y. Select centers unique uniform patches, set original green and nonUsage0. All remaining fields black/nonUsage0. Reset-ticks records initial level counts and mean.

Go phase order is binding:

1. Move **all** people forward1 at current heading, then left integer random50 and right integer random50. These turns affect the next movement, not the current one. Each ask uses a snapshot/random activation.
2. For all people: green/blue current patch adds5 awareness; black subtracts1. Set current patch nonUsage0 even if it is black. Do not implement the Info's looser “decay if not influenced” reading: black-land loss happens before peer influence.
3. Snapshot people currently well-informed or activist (awareness>=10), then activate them randomly. For each sender, snapshot **other people on the same patch** currently unaware (0<=a<5) or aware (5<=a<10), visit randomly and add1. Recipients are reselected for each sender; once a receiver reaches10, later senders do not increment it. Sender eligibility is determined at phase entry; newly informed people do not become senders in this phase. A zero-awareness person on black first becomes-1 and is **not** eligible for peer messages before the later clamp.
4. Clamp all awareness to[0,15], then source colors by predicates: activist a>=15; well-informed10<=a<15; aware5<=a<10; unaware0<=a<5. Follow code, not Info's ambiguous endpoint phrases.
5. Snapshot activists after clamp. Each chooses one currently black Moore-neighbor patch uniformly, if any, and makes it blue. This happens each tick, not merely when someone first reaches15. Earlier activists' center creation affects later available patches. Setting blue **does not reset nonUsage**.
6. Snapshot nonblack patches. Empty ones increment nonUsage; occupied centers already had age reset in phase2. If nonUsage is strictly greater than the live limit, set black; retain counter. Tick. No stop rule, even with zero people or centers.

The source `place-centers` forever button paints the hovered/clicked patch green while mouse-down, without resetting its existing counter or advancing tick. Proposed `placeCenter({x,y})` calls this operation once for an exact centered patch coordinate. Repeated brush host calls remain UI concerns. Painting may recolor a blue center green and old counters may cause immediate disappearance on the next empty tick; do not silently reset them.

Proposed additional interventions: `setPeople(readonly {x,y,heading,awareness}[])`, awareness0..15, any population size0..300 independently of the setup slider step; `setCenters(readonly {x,y,kind:"original"|"created",nonUsage}[])`, unique exact field coordinates, nonnegative integer counters. The latter replaces all center membership, sets unspecified fields black/nonUsage0, and preserves specified ages. These fixtures are not user controls. Normal center actions retain age as source does.

Read people add `awareness`; cells add `center:"original"|"created"|null, nonUsage`. Counts include `activists,wellInformed,aware,unaware,centers`. The first four sum to people count. `meanAwareness` is points/person; `meanNonUsage` averages **only current centers**, units ticks. Both are `null` for empty denominators; source `mean []` plot/monitor can error at allowed zero-population/zero-center settings. This is an explicit finite-display adaptation, not source success evidence. Level-count and average-awareness histories correspond to the two original plots; original monitors count colors, which match predicates after normal source steps. Target fixtures refresh predicate-based projections immediately.

## Pollution: source mechanism and contract

World71×63, source x=-35..35/y=-31..31, both axes wrap. Inputs: `initialPopulation`30, 0..100 step10 (setup); `powerPlants`2, 0..20 step1 (setup); live `birthRate`0.10, 0..0.20 step0.01; `plantingRate`0.05, 0..0.10 step0.01; `pollutingRate`3, 0..5 integer. Source view tick label is **years**. Setup clears land pollution0/powerPlant=false, selects unique plants, runs `pollute` on all fields (plants set pollution to rate), creates people on uniform integer patch centers with health5, source random headings, no trees. Initial total pollution is plants×rate.

Go preflight stops if there are no people; trees, pollution and RNG then remain frozen and no tick is added. Otherwise snapshot current people and randomly activate **each complete person procedure**:

1. Turn right random-float50 then left random-float50, move forward1 continuously, subtract0.1 health.
2. If health>4, draw continuous random<birthRate and hatch a person at current position/heading with health5. The strict threshold is **>4**, not Info's “4 or greater”. New people do not join this tick's outer person snapshot.
3. Draw continuous random<plantingRate and hatch a tree at the current position/heading, health5. This occurs after reproduction and before exposure/death, even if the parent has no health remaining. Source trees need not lie at patch centers.
4. Read current patch pollution before this tick's diffusion. If pollution>0.5, subtract pollution/10 health; at exactly0.5 no exposure loss. Delete if health<=0.

After all people, diffuse pollution simultaneously at0.8 across eight Moore directions, including toroidal wraps. Then `pollute` resets each plant's field to exactly current pollutingRate (not additive emission), and source caches a scaled red patch color. Then snapshot all current trees **including newborn trees** and randomly activate: mark own patch green+3, reduce local pollution by1 and each Moore neighbor by0.5, each floored at0; subtract0.1 health; delete when health<=0. Multiple trees sequentially clean the current field; their effects can saturate. A tree that dies still cleans first. Tick after all phases, even if the last person died earlier. A subsequent go preflight stops; no invented continuation of ecological dynamics after extinction.

Proposed `setRules` permits only birthRate, plantingRate, pollutingRate. Changing rate has no immediate field reset; the next post-diffusion plant phase applies it. Proposed fixtures `setPeople(readonly {x,y,heading,health}[])`, `setTrees` with the same fields (any finite health), and `setEnvironment(readonly {pollution,powerPlant}[])` with exactly4473 records in `read().cells` order, nonnegative finite pollution and boolean plant flags. Fixtures can intentionally represent non-equilibrium plant concentration and are not inferred source setup. No arbitrary tree/population cap. Trees and people are disjoint typed kinds in one World.

Read counts `{people,trees,powerPlants}`, all people/trees with health, cells `pollution,powerPlant`, totalPollution=sum of field values. World Status plot has three **different units**: counts of trees, counts of people and total abstract pollution. Do not call the third a population, mean concentration or pollution-agent count. Source Info's predator/prey framing does not describe moving pollutant agents: pollution is a scalar field. Source patch colors are stale after neighbor cleanup and sometimes show a tree's green cell despite pollution; target may color from actual latest pollution with tree/plant overlays. This is an explicit presentation improvement; field/health/order semantics stay functional baseline. Tree life is nominally50 steps but repeated binary subtraction0.1 can move its exact final death by floating roundoff; do not replace with an integer lifetime or promise an exact50-step death invariant.

## Recycling: source mechanism and contract

World35×35, source x/y=-17..17, toroidal. Setup-only `numRecyclers`25 and `numWastefuls`25, each0..50 integer. Live inputs: `maxStoredEnergy`50, 10..100 step5; `recyclingWasteCost`0.5, 0..2 step0.25; `resourceRegeneration`25, 0..100 integer; `agentsSeekResources`false; `showEnergy`true. Setup creates the two kinds, positions each at a uniform integer patch center, retains source random headings, initializes energy=max/2 and every field resource="new".

Go order:

1. Randomly activate all recyclers to process their current patches. New land: add2 only if energy<=max-2, leave new. Recycled land: add1 only if energy<=max-1, leave recycled. Waste land: always subtract recyclingWasteCost and make recycled, even at low/negative energy. No preflight death.
2. Randomly activate all wastefuls after recyclers. New land: add4 and change to waste **only if** energy<=max-4. Recycled land: add2/change to waste only if energy<=max-2. On waste, do nothing. At excess energy refuse the whole transaction rather than consuming and clipping gain. Earlier actors' land changes affect later actors.
3. Randomly activate all surviving turtles: first select a uniform random Moore neighbor as fallback. If seeking, prefer a uniform new neighbor, else a uniform recycled neighbor, else keep fallback. The initial fallback draw still occurs even when overridden. Face and move exactly to chosen patch center, subtract1 energy. Then clamp energy down to max if over it. Delete only if energy<0: **zero survives**. Live lowering of cap changes energy only after this move, not at setRules time.
4. Source labels show rounded energy if show-energy? else empty. Projection only; no influence on resources or random draws required by target.
5. Snapshot recycled fields, random activation, draw integer random100 < resourceRegeneration/10 and change passing cells to new. Then snapshot waste fields and test `(random5=0) and (random100 < resourceRegeneration/10)` before renewing. Preserve the conditional second draw on the waste path rather than precomputing both trials. Update patch colors and tick. No stop rule even with no people; the environment keeps regenerating.

The regeneration slider is **not a direct percent**: at25 the integer comparison accepts0,1,2, giving3% per recycled field, and0.6% per waste field (with an independent one-in-five first trial). At100 the probabilities are10% and2%, not100%/20%. At0 renewal never occurs although source trials still consume draws for eligible fields. Preserve this quantization. No reproduction, imitation, switching kinds or moving-resource collection is present. A person processes the starting patch then seeks; it does not immediately harvest the destination.

Proposed `setRules` accepts all five live fields; showEnergy belongs to model settings but does not modify domain dynamics. Fixtures: `setPeople(readonly {kind:"recycler"|"wasteful",x,y,heading,energy}[])`, finite energy including over-cap or negative test states, each kind count0..50; and `setResources(readonly ("new"|"recycled"|"waste")[])`, exactly1225 values in cell order. Positions for this discrete model must be exact patch centers. Replacing people does not change setup counts. Fields own `resource`; read people include kind/energy; counts are `{recyclers,wastefuls}`. `landPercentages` has keys `new,recycled,waste`, each100×count/1225 (sum100 within floating tolerance). Population history and land percentage history correspond exactly to source plots. Source label shape/size and color are projections; a target energy overlay may display the same rounded value more accessibly.

## Explicit RNG/adaptation policy and unresolved host details

Use target Mulberry32 with explicit seed, never claim NetLogo Mersenne Twister trajectory equivalence. Retain random snapshot order in behavior-dependent phases, integer versus continuous trials, uniform choices and source branch draw conditions. Omit source rendering-only color draws/shuffles and Awareness's setup `fd random25` whose position is immediately overwritten; initial headings remain uniformly integer0..359. Document actual target draw ordering and any further omission before implementation acceptance. Pure clamping, labels, plot reductions and order-independent field resets may iterate deterministically. No RNG in read, setRules or fixtures. Different activation streams and floating summation may change individual outcomes without changing these mechanisms; do not claim distribution equivalence without a justified executed study.

No headless contract gap is identified. Host work remains: shared grid view must render multiple co-located people, Pollution trees/people and scalar fields, exact centered fractional cell positions for Awareness, and the Awareness center brush through a headless action. Recycling energy labels should be supplied as renderer data, never recomputed ecological state in UI. Do not silently omit original actions if existing view adapters are insufficient: scope a separate actual shared UI capability with frontend-design and web-design-guidelines, then real browser checks. These are future integrations, not a claim that every host feature already exists.

## Public acceptance examples

All scripts use only each public model entry, ordinary assertions and detached observations; none imports private runtime, mocks, transcompiled NetLogo or disables checks. [SHA256SUMS](../../examples/selected-urban/SHA256SUMS) records the required example content.

1. [Awareness contact/expiry](../../examples/selected-urban/01-awareness-contact-and-expiry.ts): movement-before-contact, dynamic recipient exclusion at10, strict center expiry, stale age when painting, repeated activist creation, empty means and nonterminal empty population.
2. [Pollution phases/stop](../../examples/selected-urban/02-pollution-phases-and-stop.ts): exact Moore impulse8 -> local1.6/neighbors0.8 followed by dying-tree cleanup -> total3; fixed plant reset -> totals3 then5.4; extinction step ticks, later steps freeze.
3. [Recycling order/energy](../../examples/selected-urban/03-recycling-order-and-energy.ts): recycler restores before wasteful consumes shared patch, costs before movement, zero-energy survival, no automatic population terminal.
4. [Defaults/isolation/validation](../../examples/selected-urban/04-defaults-isolation-and-validation.ts): exact source dimensions/counts/initial totals, independent instances, detached frozen snapshots and atomic rejection of malformed fixtures/out-of-step rules.
5. [Live seeking/cap](../../examples/selected-urban/05-live-seeking-and-cap.ts): seek new neighbor, process origin before movement, live cap does not rewrite state immediately, refuse over-cap harvest then clamp after moving.

Additional behavior tests must cover wrap boundaries, strict exposure0.5/birth>4, new births excluded but new trees included, threshold-receiver transient negatives, exact stale ages, over-cap gates, regeneration quantization, repeated centers, no-RNG observations and zero-step/invalid counts. Five scripts deliberately do not exhaust these edge cases.
