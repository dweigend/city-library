# NW generator variants: bounded public authoring proposal

**Preparation only. No runtime authorization, API acceptance, freeze or independent approval.** Exactly five complete asserted public scripts are proposed under [examples/nw-generator-variants-proposal](../../examples/nw-generator-variants-proposal/). Current types/runtime are expected to reject the proposed additions. All existing eleven-kind GeneratorOptions branches, defaults, caps and five frozen generator scripts remain authoritative and unchanged.

## API alternatives requiring a coordinator decision

The bindings do **not** prescribe a new public name, option, profile tag or Kleinberg kind. The following alternatives are reviewable choices, not inferred permissions.

| Choice | Benefits | Costs and boundary |
| --- | --- | --- |
| **A: an explicit source-topology profile on existing `generate`, plus Kleinberg** | Makes a coherent opt-in group of source-backed operational choices visible. Existing PA/WS defaults and directed rejection stay intact. One existing method/return type/owner/atomic batch can remain. | A source-branded tag needs a pinned semantic edition and could overclaim full NetLogo compatibility. It still needs precise per-branch fields. Births, native RNG, layout and shuffled blocks remain outside it. |
| **B: individually named mathematical/operational variants** | Makes reusable distinctions visible without tying all choices to a source release: e.g. a Kleinberg family, link-end attachment, remove-old rejection rewiring, inward spokes and long-axis-only seams. | More names and combinations need their own closed validation. Link-end/rejection RNG schedules are operational contracts, not consequences of a mathematical family name. A Kleinberg law alone does not decide attempt/dedup/CDF order. |
| Separate new generator method or model-private adapter engine | Could segregate compatibility at a new surface. | Duplicates the existing owning construction boundary and risks a second implementation of topology/atomicity. Not proposed for implementation here. A thin action adapter may compose public operations, but must not hide a reusable private graph engine. |

The five scripts instantiate **A only as working notation**: literal `profile: "nw-web"`, new `kind: "kleinberg"`, `neighborsPerSide`, `clusteringExponent` and `spokes`. Those spellings and the tag's versioning require root approval. They are deliberately absent from source/exports. The candidate profile is a topology-only subset, not a promise to emulate all ten primitives, NetLogo RNG or turtle creation.

Proposed additional branches, for review—not a declaration installed in the package:

```ts

| { kind: "kleinberg"; profile: "nw-web"; nodes: readonly N[];

| { kind: "preferential"; profile: "nw-web"; nodes: readonly N[];
    links: number; directed?: boolean; random: Random }
| { kind: "smallWorld"; profile: "nw-web"; nodes: readonly N[];
    neighborsPerSide: number; probability: number;
    directed?: boolean; random: Random }
| { kind: "wheel"; profile: "nw-web"; nodes: readonly N[];
    directed?: boolean; spokes?: "in" | "out" }
| { kind: "lattice"; profile: "nw-web"; nodes: readonly N[];
    shape: readonly [number, number]; wrap?: boolean; directed?: boolean }
```

These affect `GeneratorOptions`' exported union and Graph's private generator dispatch/atomic planner. No new Graph method, result type, Random API, World ownership, registry or top-level numeric API is proposed. Optional existing flags retain `undefined` defaults inside an applicable branch. Proposed concrete-profile dispatch would reject own `profile: undefined`, unknown tags and profile-inapplicable keys; old branches continue their existing own-key rules. In particular old `preferential` and `smallWorld` still reject `directed`, even when its own value is undefined. In the proposed WS profile, `neighbors` is foreign and `neighborsPerSide` is required; the original field is never silently reinterpreted.

Star and outward-wheel cases already have public compositions, so A adds no new star branch. A profile-free directed star followed by `copy({direction:"reverse"})` gives canonical leaf-to-first-hub edges. A subsequent undirected copy retains that stored endpoint order. For an outward last-hub wheel, passing `[lastHub,...rim]` to the existing generator changes generation order without changing Graph node insertion/identity order. Reversing a whole outward wheel also reverses its rim, so it does not give the source's inward wheel. The proposed wheel branch handles that remaining selective-orientation gap in one owning batch. The generic ring's empty/singleton/two-node behavior remains unchanged; native ring minimum-three validation is an action/source-domain concern requiring its own adapter decision, not a hidden change here.

## Source-backed behavior versus proposed closure

| Family | Source fact retained from the actual audit | Candidate topology contract and unresolved choices |
| --- | --- | --- |
| Kleinberg | Row-major right/down base lattice; wrap seam only for an axis longer than two. Each source considers every other row-major cell, including current neighbors. Manhattan/toroidal-Manhattan weights `d^-r`; ordered Number cumulative sum; one draw if total positive, inclusive `pick <= cumulative`, last-candidate fallback. `linkOnce` suppresses an existing ordered/unordered pair without redraw. | Shape `[columns,rows]` preserves existing x-fastest convention; both integer axes at least two and exact node product. Require an explicit finite nonnegative exponent; default wrap/directed false. One attempt per node, not guaranteed one new edge. Exact numeric/exponent domain and the operational Number policy require approval; examples cover r0/r2 only. |
| PA | Seed is the first `m+1` nodes with i→j for i<j when directed. Every attempt chooses an existing stored link then one of its endpoints. Duplicate targets retry. The pool stays fixed until a new node's m distinct choices complete. Links append new→old in choice order. Both link ends count even for directed edges. | `links` integer in `[1,n−1]`, optional directed false. Same undirected topology law can differ operationally from generic CDF sampling. Proposed portable selectors use the existing explicit Random: one unit-derived integer index, then one unit `<.5` for end1. Variable rejection count and no arbitrary attempt cap. This mapping is new and must be approved; it is not native raw-RNG equivalence. |
| WS | Source k is per-side, `0 <= k <= ceil(n/2−1)`, n positive. Full forward seed adjacency is preloaded. One probability decision per source/offset. On rewiring remove the old target first; it becomes eligible. Persistent candidate buffer, partial Fisher–Yates selectors, reject self/either-direction neighbors. | New `neighborsPerSide` integer `[0,floor((n−1)/2)]`, n≥1; retain probability `[0,1]`, optional directed false. n1/n2 with k0 have no topology edges/draws. The n2/k0 case was actually probed; n1/k0 follows source validation/empty loops, not a separate native probe. Propose one existing-Random unit index per buffer trial, including singleton remainder; source traversal/preload/buffer persistence remain explicit. |
| Wheel/lattice | Rim-first/last-hub wheel, ascending rim then spokes; inward/default wheel points toward hub, outward away. Wrapped two-cell axes suppress seams, including directed lattice. | Wheel n≥4, proposed default `spokes:"in"`; lattice exactly two integer axes ≥2, right-then-down order and long-axis seams. Generic first-hub/outward wheel and directed antiparallel two-cell lattice remain unchanged. Hub order, stored undirected endpoint order and default spelling still need root approval. |

For the ideal Kleinberg law, a 2×3 corner at r2 has probabilities `[18/47,9/94,18/47,9/94,2/47]`; wrapped 3×3 has axial `1/5`, diagonal `1/20`. Operational binary64 accumulation is a separate precision choice, especially for extreme exponents/tiny cumulative increments. The primitive's helper does not establish a reliable integer/nonfinite/exponent domain; the UI's 0…10 exponent and 0…20 row/column widgets are observed controls, not automatically general API caps. The proposal does not invent a 20-cell-axis limit. Numeric and rejection-policy questions must close before any freeze.

For PA, a stored pool of L links gives each node mass equal to its number of incident link ends divided by `2L`, including both directed ends. Rejection of already chosen targets conditions those original masses without updating degrees until the batch completes. This can share the generic degree-proportional conditional law while using a different selector/rejection schedule; direction, upper-triangular seed and stored endpoint order remain substantive separate choices. For Kleinberg, preserving an inclusive zero pick when a computed weight underflows to zero also needs an explicit numerical decision; the ideal strictly positive real law is not itself proof of that floating behavior.

All proposed branches retain current canonical selected-node membership, induced-edgeless preflight, cloned defaults, no fabricated geometry, source-order ownership and atomic publication. Existing per-call caps remain **100000 selected nodes / 1000000 actual new edges**, never candidate trials or a global Graph cap. Known PA/WS/lattice edge counts preflight before draws; stochastic failure must retain already consumed units and publish no partial topology. Kleinberg base/one-attempt output has a small edge-count bound relative to nodes, but naive all-candidate probability work can still be quadratic. No extra runtime candidate cap or implementation shortcut is authorized by this proposal.

## Action/RNG boundary that remains a real model gap

The original does random color/heading births for most generators, interleaves PA births with topology, gives WS ordered no-birth-RNG turtles, and always runs an agentset-shuffled block—even when omitted/no-op. The ordinary all-alive final shuffle consumes n−1 native integer selectors. Layout, clear/append and plots are further model actions. A single headless call on already existing nodes cannot reproduce interleaved PA birth draws by merely resetting one Random seed, nor can it infer the final block/layout protocol.

Script05 deliberately chooses separated author streams and an existing portable `Random.sample(...,{compatibility:"legacy-shuffle"})` caller action. That is an explicit alternative action policy, **not** a native ask-order implementation. No exact native RNG bit parity is promised: the delivered Random is Mulberry, while the audit pins source selector calls and native fixtures, not a common stream bridge. Root must decide whether selected-model acceptance permits this declared alternate action policy, requires a separately approved native RNG/birth/action adapter, or remains blocked pending that work. This proposal supplies no new public birth/block/action API and does not hide those unresolved protocols inside generate.

## Decisions required before acceptance or freeze

1. **Public vocabulary and affected types:** choose profile A versus named variants B; approve/replace `profile`, `"nw-web"`, `"kleinberg"`, `neighborsPerSide`, `clusteringExponent`, `spokes`, profile edition/versioning and new union branches. Existing binding names do not authorize any of them automatically.
2. **Profile scope/defaults:** approve the five candidate branch contracts, wheel inward default and deterministic domains; keep star/outward-wheel compositions and native ring minimum separate. Decide concrete-profile-only dispatch and undefined/foreign-key precedence without weakening existing branches.
3. **Kleinberg numeric closure:** integer dimensions/product, exponent domain (candidate finite≥0), binary64 ordered Math.pow/cumulative/inclusive-CDF semantics, tiny weight underflow and zero-effective-probability meaning. The selected r0/r2 examples do not establish arbitrary exponent behavior.
4. **Portable random mapping:** approve or replace one-unit integer indices and `<.5` endpoint mapping. Establish that native-selector structure, portable continuation and source/native bit parity are three different claims. Keep library-issued Random validation and Gaussian cache rules.
5. **Rejection/performance:** approve PA variable attempts without an invented cap, WS persistent buffer across all source slots and singleton index draws, inherited stochastic-cap stopping, and an efficient atomic owner integration. Candidate work is not a generated-edge cap.
6. **Model action/native comparison:** explicitly choose birth/topology interleaving, final shuffled/no-op blocks, append/clear, layout and plot adapter responsibilities before asserting selected NW model equivalence. No universal source adapter follows from the topology additions alone.
