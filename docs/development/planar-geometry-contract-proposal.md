# Planar geometry: contract and five public example proposals

Status: **proposal only; no freeze, implementation authorization, runtime or independent approval**, 6 November 2026. This scoped task preserves existing authoring names and target types. The coordinator must review the five scripts, resolve the questions below, then accept and fingerprint a final example set before delegating runtime. No existing binding text, source data, ledger, configuration or public export was changed.

## Existing contract and bounded closure

[Pure spatial contracts](../agent-loom/api-reference.md#pure-spatial-contracts) already specify:

```ts
geometry.contains(polygon: PlanarPolygon, point: { x: number; y: number },
  options?: { boundary?: "include" | "exclude" }): boolean
geometry.bounds(features: PlanarDataset | readonly PlanarFeature[]): Bounds | undefined
geometry.map(point: { x: number; y: number }, options: {
  from: Bounds; to: Bounds; mode?: "uniform-centered" | "independent-axes"
}): { readonly x: number; readonly y: number }
```

`Bounds` is `[minX,maxX,minY,maxY]`, **different from SHP XY header order**. The already specified type names are `PlanarXY`, `PlanarPolygon`, `PlanarGeometry`, `PlanarJson`, `PlanarFeature` and `PlanarDataset`, retaining their exact definitions from the reference. Scripts import those names and `geometry` from `city-library`; no local replacement API, assertion helper module or private import is supplied. Public `Random`/`World` in script04 are already delivered and only witness unchanged model clock/RNG state.

This is limited to three headless methods and their public types. It introduces no parser/codec, storage implementation, CRS transform, GIS engine, agent factory, renderer, extra geometry operation or resource-export slice. Existing [GeoJSON codec](../agent-loom/api-reference.md#complete-external-codecs) semantics inform validation but do not make a JSON/SHP decoder available. Existing runtime `geometry` currently exports direction/normalize/distance; missing three-method/type exports are expected preparation failures, not grounds to weaken accepted API design.

Normative behavior preserved: shell first, holes afterward; strict closed finite XY rings with noncollinear vertices, no zero-length edge/self-intersection; holes strictly internal, no touching/crossing/overlap; winding immaterial; boundary include/exclude applies to both shell and holes. `bounds` traverses every non-null geometry, permits zero-width/height results and yields undefined with none. `map` defaults uniform-centered, supports independent axes, requires positive finite widths/heights, returns unclipped transformed outside points and makes no geodesy/CRS inference. Observation allocates no Agent/World/Grid, mutates no input and consumes no clock/RNG.

Future runtime, if accepted, must remain in the binding geometry domain layout with deliberate root exports; hosts supply data, and experiments/UI consume public operations. Source-specific adaptation cannot be hidden in a new private model geometry engine.

## Questions that must be resolved before acceptance

The [resource-budget section](../agent-loom/api-reference.md) gives hard constants, but its scope sentence says planar dataset parsing/writing and containment. It does not completely define how every in-memory `bounds`/`map` argument is traversed or counted. The table makes each proposed choice explicit rather than silently broadening a binding adapter.

| ID | Unresolved contract and proposed interpretation | Proposed script consequence |
| --- | --- | --- |
| U1 | **Budget and validation scope.** Should bounds validate a complete dataset including labels/properties/features/budgets even for null/empty geometry? Proposed yes, consistent with plain finite PlanarJson and invalid-polygons-before-bounds language. `map` has only point/envelopes/options, not dataset or JSON text; no feature/property/text budget is proposed for it. Root must settle bounds scope rather than infer it from parsing/writing. | 04 asserts invalid CRS/properties reject even with no coordinates; 05 applies in-memory feature/position/property/coordinate caps to bounds. |
| U2 | **Strict object descriptors.** PlanarJson requires plain JSON data, but pure geometry text does not explicitly repeat Agent shared-value descriptor rules for all geometric records/options. Proposed own string-keyed data properties and plain object/null prototypes, reject symbols/accessors/custom prototypes/cyclic property or geometry graphs without invoking getters. Proxies remain unsupported inputs, with no claim of universal detection. Root must settle rejection timing/error type. | 04 checks no getter execution and no prototype mutation; those are proposed policy assertions, not established geometry runtime evidence. |
| U3 | **Position counting.** Proposed count every XY tuple occurrence across all features and recursive collection/multi members in a single bounds invocation, including repeated closing vertices; no counter shared across calls. Does a contains query point count toward positions, or only the polygon? Proposed polygon tuples only, query validated separately for finite shape and coordinate magnitude. | 05 allows100000 MultiPoint tuples, rejects one extra feature/collection point; at2048 polygon positions plus query remains allowed. |
| U4 | **polygonPositions=2048 scope.** Proposed sum exterior+hole rings for one PlanarPolygon, including each closure; reset for each MultiPolygon member. Never equate one SHP multipart country record with one Polygon before shell/hole grouping. MultiPolygon-member overlap/touch rules are not separately specified; examples use disjoint members and impose no new global validity rule. | 05 tests shell+hole total2048 accepted/2049 rejected and two disjoint2048-position Polygon members accepted under total positions budget. |
| U5 | **Property nodes/depth/aliases.** Proposed propertyNodes counts all value occurrences including root record, containers and scalar/null leaves, aggregated across validated property roots in one call; properties:null is the empty absent property object for budgeting. propertyDepth counts nested containers with root container depth1, scalar children do not add container depth. Acyclic aliases count on each occurrence, cycles reject. This choice bounds traversal work without pretending aliases are JSON identity. Root may choose another documented interpretation before freeze. | 05 tests32/33 nested containers and100000/100001 nodes; shared array twice exceeds occurrence budget. No present binding text explicitly fixes this arithmetic. |
| U6 | **GeometryCollection structural depth.** No geometry nesting ceiling or independent geometry-node budget is specified. Do not repurpose propertyDepth/propertyNodes for geometry collections silently. Proposed iterative/cycle-safe traversal; either bounded geometry structure needs its own explicit accepted rule or finite coordinate-free nested collections remain within documented counters. | 02 tests modest nested/empty collections; 04 rejects an actual cycle. No invented numeric nesting ceiling or empty-collection exhaustion assertion. |
| U7 | **Foreign members.** Reference says unknown foreign members are not silently interpreted as coordinates; it leaves ignore/preserve/reject and validation/counting of their values unclear. Proposed defer rather than freeze extra-member policy. Recognized properties containing a `coordinates` name are ordinary properties. | 02 tests a known properties object with coordinate-looking names. No assertion about unknown foreign top-level members; accepted policy must add focused checks before runtime if in scope. |
| U8 | **Default boundary.** contains supports omitted options but the boundary default is not explicitly stated in the cited section. No invented default at a boundary. Proposed include is a possible choice, not binding here. | Positive boundary witnesses always supply include/exclude. Calls omitting options in04 use already-invalid arguments, so do not freeze a default. |
| U9 | **Numeric robustness and errors.** Need robust orientation, segment crossing/touch and ring containment for finite binary64 inputs without an invented epsilon or undocumented coordinate rounding. Adjacent shared endpoints are allowed, nonadjacent self-touches and hole contact must reject. Reference distinguishes wrong shapes/options TypeError versus domain/arithmetic RangeError but does not completely classify topological invalidity, nonfinite scalar errors or validation precedence. Proposed exact representable-coordinate predicates; expert advisory decision still pending. | 01 uses exact moderate-size fixtures and generic throw for topology. 04 checks TypeError on explicit wrong shapes/data and generic throws on nonfinite values. 03/05 assert RangeError for extents and count limits. The1e9 square is an additional large-offset exact witness, not proof of full robust geometry. |
| U10 | **Magnitude and arithmetic coverage.** coordinateMagnitude=1e9 is named for the planar adapter/containment profile. Root must confirm bounds inclusion and whether map's generic affine inputs have that cap, or only finite/positive-domain checks. No widening of the constant is proposed. Overflow/intermediate failure and exact validation order also need a recorded decision. | 05 tests ±1e9 bounds and1e9+1 rejection under U1. 03 tests moderate finite affine inputs; no assertion silently caps generic map or changes other geometry operations. |

Constants preserved exactly: textBytes8388608, features10000, positions100000, polygonPositions2048, coordinateMagnitude1000000000, propertyDepth32, propertyNodes100000. No call documents lower/higher caller caps here, so no such options are invented. textBytes is a serialized parser/writer budget and no text API is part of these three methods.

Unresolved rows are not permission to change existing signatures/types; they are a request to record missing semantics before acceptance. The scripts must be reviewed as proposals as a whole, particularly04/05. Do not mark contract-frozen merely because they parse or because a convenient implementation can satisfy them.
