# Independent Graph.copy: contract proposal

Status: design/example proposal, 6 November 2026. Exactly five public scripts propose the existing [copy binding](../agent-loom/api-reference.md#graph-views); no runtime, API freeze, independent approval or delivery increase is included. This slice returns an actual full **current** Graph. It does not implement `view`, fabricate a `ReadonlyGraph`, add unsupported query placeholders, or create a new public API.

The real NW source need is topology/direction adaptation while retaining canonical turtle identities. [Source gap evidence](nw-generator-source-gaps.md) establishes inward-star, last-hub wheel and other differences. Independent copies permit explicit experiments on shared nodes; copying/reversing alone does not implement directed PA, native WS RNG/eligibility, or Kleinberg, and does not repair a wheel's hub ordering or selectively reverse only its spokes.

## Binding facts and bounded examples

The signature remains `graph.copy({ nodes?, edges?, direction? }): Graph<N,E>` with direction `original | reverse | undirected`. Omitted selection means all current nodes and all induced edges. Explicit arrays are identity-deduplicated entry snapshots; every selected identity must currently belong to the source and every selected edge must have both endpoints selected. Nodes remain the original canonical objects. Edges have fresh independent identities and cloned model state/path. Representation options and insertion order are preserved. Reverse changes directed endpoints/path only; undirected preserves every edge, enabling parallel representation when opposite directed connections collapse onto one simple pair. Shared Agents are neither cloned nor attached to a World.

All currently constructible Edges have `path: undefined`; all five scripts use only that actual surface. No future path constructor, test stub, or invented geometry field appears. When a real Edge path API exists, its documented cloning and reverse-orientation behavior will need its own executable examples.

## Current source constraints

Read-only source inspection covers [graph.ts](../../src/graph/graph.ts), [edge.ts](../../src/graph/edge.ts), [collections.ts](../../src/graph/collections.ts), [state.ts](../../src/agent/state.ts) and [lifecycle.ts](../../src/agent/lifecycle.ts). [Source snapshot](graph-copy-proposal-evidence/source-snapshot.json) records exact hashes for these and the public binding. The current kernel has no `copy` member or implementation. Its generator publication batch prepares connections/states before adding edges; copy needs an analogous private preparation boundary, not generator-specific validation or caps.

`nodes.add` immediately registers a deletion participant on a living Agent. Constructing a target then incrementally cloning edges can therefore leak a partially constructed owner through Agent hooks when a later clone fails, even if the target was never returned. Required implementation sequence for review: capture/validate source membership, selection and options; prepare and validate all cloned defaults/states/path values and representation/key decisions; revalidate prepared framework-reference liveness after all reflection has completed; only then create/publish the new owner, register its memberships, and materialize its complete edge set without running caller code. Prepared plain clone data allows this final liveness pass without rereading hostile original state. No new public transaction abstraction is proposed. Private lifecycle checks must establish that failed copies leave hook counts unchanged; public examples cannot directly count those hooks.

`cloneEdgeState(edge)` is not a valid implementation: a registered Edge is not a plain model-state root and contains reserved framework members. State extraction needs descriptor-safe separation of model properties from actual framework-owned fields before the existing supported-value clone rules are applied. Blind spreading also invokes getters. Cloning must preserve a living framework reference as that original reference, not remap original Graph/Edge references to the new owner or new edge. Deleted framework references remain invalid under current clone rules.

The shared clone facility preserves internal cycles and aliasing per call, clones supported containers/buffers, rejects custom prototypes/accessors/symbol properties and nonfinite model numbers, and retains living framework identities. There is no callback argument in copy, but reflection on hostile Proxy objects can execute caller traps; a source read guard should cover preparation and reject structural reentrancy. This is not a promise that JavaScript can detect all proxies or undo their external side effects. Ordinary mutable model fields still obey the caller purity requirement, not a new transaction system.

The collection guard applies to both source collections. A copy is a read on the source, so it should remain legal inside an active source collection iteration; mutation of the resulting independent graph must not fail merely because that source reader is active. Node/edge deletion in the source during preparation must be guarded. Agent deletion validates every participant before committing, so the source guard also prevents partial source lifecycle mutation. Guard release on every failure requires focused integration checks.

Do not reconstruct via a large loop of public `edges.add`: that method scans existing edges for simple-pair validation, giving quadratic construction. Prepare pair/key indexes once and use an internal owner batch. There is no 100000-node or 1000000-edge bound in copy's binding. The node boundary example exceeds the generator limit; no million-edge fixture is manufactured through the quadratic public add path. An efficient larger edge-copy integration fixture should use existing bounded generator batches and validate counts/identity, without inventing a copy cap.

## Unresolved decisions and proposed closures

All proposed closures below need explicit parent review before freeze. The five scripts encode them so the consequences are concrete.

- **U1 — source order versus explicit selection order.** “Identity-deduplicated entry snapshots” does not say whether an explicitly reordered selection controls output order; “preserves insertion order” favors source order. Proposal: capture nodes/edges at call entry, use identity sets as filters and preserve source node/edge insertion order regardless of array order. `edges` omitted selects the induced edges of selected nodes; `nodes` omitted retains all nodes even if an explicit edge list is narrow. Reject foreign entries and selected edges with unselected endpoints instead of silently filtering them. Script01 distinguishes these choices.
- **U2 — keys and automatic counters.** “Representation options” does not explicitly specify key retention or copying a private key cursor. Proposal: preserve existing parallel edge keys exactly; simple copied edges remain keyless unless undirected conversion requires parallel promotion. On promotion assign automatic keys in copied edge order. Start a fresh graph's automatic cursor at zero and skip occupied retained keys; do not inherit the source's historical cursor. Preserve `parallel:true` and `selfLoops:true` even for an empty/restricted selection. Script02 distinguishes fresh cursor from historical cursor and preserves loop/state multiplicity.
- **U3 — clone sessions/defaults/framework references.** The binding names edge model state/path but omits graph defaults and cross-edge alias scope. Proposal: independently clone owner defaults once and each selected edge state in its own clone session, preserving aliases/cycles inside each state but not creating new cross-edge aliases. Preserve framework references exactly as current state cloning does, including references back to source Graph/Edge; never rebind them implicitly. Validate/clone defaults even for an edge-empty copy so later `edges.add` has an independent, usable default. Consequently a dead reference in defaults rejects an empty copy. No promise to restore aliases already broken by original independent edge additions. Scripts03/04 distinguish defaults from edge state and require original framework identities.
- **U4 — preflight/guards/failure atomicity.** Binding does not detail hooks or errors occurring during cloning. Proposal: full clone/representation/selection preparation under the source read guard before any target owner/Agent hook is published; all reflection failures propagate, and guards always release. Permit nested source reads and independent target edits. No callback rollback, public transaction, global-ID sequence promise, or mutation of source defaults is introduced. Public failure examples need private hook-leak and reentrant-reflection integration checks during implementation.
- **U5 — strict option/array domains and error precedence.** Proposal: use the existing plain-data option convention, reject unknown own keys even if undefined and reject accessor/symbol keys without invoking getters. Optional recognized undefined fields mean omission. Explicit selections must be dense data arrays, with no accessor indices, holes or extra own properties; no generator size limit transfers. Validate shape/options first, then complete membership/endpoints, then clones, then publication; composite-invalid cases need no new public exact error-message/order promise. Script05 does not claim Proxy detection. Source `validateOptions` supports Object/null prototypes; no additional prototype rule for array subclasses is frozen here because the five scripts do not distinguish that issue.

## Executed checks and limits

[Validation evidence](graph-copy-proposal-evidence/validation.json) separates the following:

- All five scripts parse/transpile with Bun; proposal type diagnostics are retained. The **only** proposal TypeScript errors are missing `Graph.copy` (`TS2339`), rather than hidden implementation or shim passes.
- `bun run typecheck` passes for the actual current repository source/configured suites. The proposals are deliberately outside the configured delivered example set.
- [Executed source oracles](graph-copy-proposal-evidence/verify-source-oracles.ts) pass against actual root APIs for current clone semantics, keys/opposite arcs, collection guards and Agent lifecycle. They do not call `copy` or certify its future behavior.
- A separate small topology oracle verifies the labeled reversal and undirected pair multiplicities in the proposed fixtures. No generator or copy implementation is embedded in the evidence.

The five proposed copy scripts cannot pass against today's runtime because `copy` is absent. No browser verification is applicable to this headless design-only scope. No build, complete runtime regression, independent review, baseline acceptance or API freeze is claimed. Parent review and explicit closure of U1–U5 precede any runtime handoff.
